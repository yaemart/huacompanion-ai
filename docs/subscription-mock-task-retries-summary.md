# 本地模拟重试与待核对：本轮亲测

本批先完成服务层，没有新增按钮、后台常驻任务或真实发送。获独立主题授权的主管只能处理本人当前活动，原模拟确认、来源、退订、暂停和取消门槛继续有效。

## 怎么亲测

使用 Node24.22.1，保持本机演示 PostgreSQL 运行，在项目目录执行：

```sh
npm run test:subscriptions
```

脚本创建随机测试库、应用迁移，运行26组虚构测试后清理。最后应看到：

```text
PASS 本地模拟重试、固定正文任务键、退避与五次23小时门槛、待核对、中断并发和审计回滚
```

不必手动改数据库或等23小时；脚本只推进随机库中的测试记录来演练到期，不改电脑时钟、原数据或图片。失败时记录时间、命令和最后错误，不附密码、邮箱或领取凭证。

## 本轮能验证什么

- 领取不算尝试，开始时才冻结正文和任务唯一键。两个进程重复开始只记一次；重试仍使用同一份内容，不再占一份营销额度。
- 临时失败按30秒起的指数退避；429有更长等待要求时遵守它。最多5次，从首次尝试起最多23小时，等待超出窗口也停为待核对。
- 结果不明，或开始后进程中断、租约到期，都停为待核对，不自动换键再发。只领取但尚未开始的任务仍可正常恢复租约。
- 永久失败停止该任务；“模拟完成”只表示本地结果，不表示供应商接受、邮件送达或客户阅读。
- 重复结果不重复记审计，旧凭证不能覆盖新尝试；旧完成接口不能绕过等待和待核对。审计提交失败时，尝试和租约修改全部回滚；审计按尝试主键关联，详情另记份额编号。
- 配置或来源变化、撤权、退订和新同意版本仍会阻止旧任务；恢复配置不会自动恢复旧模拟确认。原历史、已占份额和余额保留。

本批没有浏览器操作或真人验收，也没有清除“待核对”的入口。后续再接状态汇总、人工核对和调度；跨确认/资料邮件的共用尝试预算、全站限速、真实回执和全局拒发仍待后续，不据本服务开放真实发送。原确认/资料限额不变，停止点C照旧。
