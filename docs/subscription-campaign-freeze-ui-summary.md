# 政策群发：手动冻结与人数汇总亲测

本批把上一批的名单快照接到中文活动页面。主管可以先模拟、逐语言确认，再手动“冻结本轮名单（不发送）”；页面显示所属版本、编号、北京时间及中英文人数，全部标为暂存未发送。预估和冻结共用同一邮箱、最新同意、隐私及语言口径。

## 启动和关闭

使用 Node 24.22.1，保持演示 PostgreSQL 运行，在项目目录执行：

```sh
npm run test:subscriptions -- --preview
```

打开 `http://127.0.0.1:3186/admin`。终端显示本次 `preview-accounts.json` 路径，里面有管理员、两名主管和运营的随机账号密码。独立随机库自动应用现有迁移，不升级原 3100 演示或覆盖旧资料。结束按 Ctrl+C，临时库、账号和副本清理；重启恢复初始样例。

## 建议亲测顺序

1. **管理员**从仪表板进入“政策群发草稿与主题授权”，给“预览主管1”授权。管理员自己操作活动也须明确授权。返回后台，打开菜单“登出”，等回到登录页再换账号。
2. **主管1**打开同一入口，选择虚构政策并保存。未测试或只测试没逐语言确认时，“冻结本轮名单”应不可用。
3. 生成模拟邮件，检查双语正文、来源和日期，分别勾选确认可读。此时可点“冻结本轮名单（不发送）”，应显示快照编号、版本、时间和人数，状态为“全部暂存，未发送”。示例现有中文4人、英文0人；有英文正文仍须确认可读，不擅自改收件语言。
4. 修改政策但先不保存，应要求先保存，模拟和冻结操作禁用；已有快照保留。保存新版后，旧模拟结论失效，快照仍标明旧版，并提示“改版续发尚未开放”。同一活动的旧快照不会被替换。
5. **权限**：运营无权操作；获授权主管2不能打开主管1的活动。管理员撤销主管1授权后，主管1重开旧链接也应拒绝。不要使用真实邮箱或开启真实邮件开关。
6. 手机或窄窗口查看按钮、日期、人数及长内容换行。反馈记录账号角色、操作步骤、预期、实际和截图，不附密码。

无新迁移、环境变量、依赖或原演示种子。本批尚未接入调度、额度、发送前实时资格核验、拒发回执或改版续发，暂存不能用于真实发送。已知轻微项：管理员在请求中仍能改授权下拉选项，跳转后未提交选项可能丢失；未保存提示的“下方”措辞待改。预估与冻结都按主题读取记录，规模增长前需优化扫描成本。
