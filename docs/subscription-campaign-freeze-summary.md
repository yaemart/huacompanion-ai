# 政策群发：本地收件快照与暂存任务

本批先做服务层基础，后台没有新增按钮。有效的本地模拟确认后，系统可以固定当时符合条件的收件人数和订阅同意版本，建立不可发送的暂存任务。**没有真实发件，也没有给任何 worker 加入可运行任务。**

## 本批能验证什么

- 只接受获授权主管本人最新草稿，管理员自己也须明确授权；没有有效模拟确认、来源变化、撤权或非本地环境均拒绝。
- 只收政策更新主题中已确认、隐私版本有效且有对应语言资料的人；未确认、已退订、旧隐私版本、缺语言者排除。同邮箱规范化后只取最新记录，较新的退订不能被旧确认覆盖。
- 首批最多 1,000 人，1,001 人时整批拒绝，不静默截断。重复或并发冻结返回同一个快照，不加入后来订阅者，不额外复制邮箱。
- 快照、暂存任务和审计一起提交；保存失败不残留部分名单。主管只拿到时间、编号和人数，不获得邮箱或逐人任务清单。

## 怎么在本机验证

使用 Node 24.22.1，保持演示 PostgreSQL 运行，在项目目录执行：

```sh
npm run test:subscriptions
```

命令会自动创建随机临时数据库，应用迁移，用虚构政策和账号运行全部 17 组订阅集成验证，退出后清理。最后应出现“PASS 本地收件快照、同意与语言过滤、并发去重、不补新人、千人上限、权限和审计回滚”，并正常结束。失败时保留终端错误、操作命令和时间反馈，不附密码或环境文件。不要自行在原演示库执行迁移或清空数据。

本轮 `npm run check` 的 353 项单元测试及类型、格式检查通过，lint 445 条既有警告未增加。检查及原始报告保存在本机忽略目录，不作为上传的 PR 附件。本批无新页面，因此没有本批浏览器截图或真人操作通过声明。

## 后续边界

暂存任务只有“暂存”状态，尚未接入发送资格、发件额度、worker、重试、退订竞争或拒发回执。冻结之后退订不会改写历史快照；未来每次发送必须重新复核当前同意，不能直接拿此名单发送。同活动改版续发本批明确拒绝，保留原快照，待后续实现。
