# Private voice messages and speech jobs

Enable `voiceMessages` in support settings. No media files are written to public uploads: mono 16-bit PCM WAV bytes live in the private `support-voice-audio` collection. All direct collection access is denied. The authenticated GET endpoint checks the visitor session's conversation ownership or the staff member's team scope before returning audio with private/no-store headers. Backups of the database contain audio and must receive the same protection as conversation records.

The browser uses microphone permission and Web Audio to record mono PCM WAV, capped at 60 seconds. This deliberately supports one format that the server can completely validate without a codec binary. `ffprobe` is not installed. WebM/MP3/MP4 uploads are rejected. Server validation derives duration from sample count, sample rate and alignment, and rejects unexpected chunks, compressed codecs, invalid headers, overlong audio and malformed/truncated files. Uploads are bounded to 6 MB and 15 seconds, four new uploads per conversation per minute, and 100 per conversation. Administrators can lower the duration (1–60 seconds), size (16,044–6,000,000 bytes) and uploads/minute (1–4) in support settings; the hard safety caps cannot be raised. Generated speech also observes the configured duration and size caps. Idempotency keys bind to the content digest and actor. Audio upload does not automatically send the recording to an AI provider.

## API

- `POST /api/support/voice?conversation=ID` with raw `audio/wav`, `Idempotency-Key`, same-origin request and visitor cookie. Add `&staff=1` for staff authentication. Returns `{audio,seconds}` and atomically appends a public voice message.
- `GET /api/support/voice?audio=ID` (same staff parameter) returns permissioned WAV bytes. No public URL exists.
- `POST /api/support/voice/jobs` with `{conversation,message,kind:"transcribe"|"synthesize",consent:true,key}`. Requires explicit per-job processing consent and the conversation's existing customer AI consent. Staff cannot override missing customer consent. Public messages only; synthesis text capped at 4000 characters.
- `GET /api/support/voice/jobs?job=ID` returns scoped status, sanitized error and result audio ID. Transcripts are stored on the original message's `voiceTranscript`, never treated as system instructions. The shared privacy heuristic routes sensitive transcripts to staff and fences pending AI reception. Synthesis refuses text flagged by that heuristic. Raw audio cannot be reliably redacted before transcription: the consent checkbox explicitly authorizes sharing the original audio/text, including possible personal information. This heuristic does not claim complete personal-data detection.

## HTTPS speech adapter

Set all of `SUPPORT_SPEECH_ENDPOINT` (HTTPS URL), `SUPPORT_SPEECH_KEY`, and positive `SUPPORT_SPEECH_DAILY_UNITS`. Enable `transcription` and/or `speechPlayback` settings. Absent configuration makes these unavailable. The endpoint is an operator-configured adapter service, not a claimed built-in integration with any provider.

The worker sends a Bearer-authenticated JSON POST: `{kind,locale,format:"wav-pcm16-mono",maxSeconds:60,maxCharacters:8000,audio?:BASE64_WAV,text?:STRING}`. For transcription return `{text:STRING}` (1–8000 characters); synthesis returns `{audio:BASE64_WAV}` satisfying the same strict upload validation. Redirects are refused, network processing has a 25-second deadline, and response size is bounded. Provider failure details and credentials are never returned to the client.

`runVoiceJob(payload, optionalAdapter)` claims one durable queued job. An injected adapter implements `run({kind,locale,audio?,text?,signal})` and returns `{text?,audio?}`; useful for deterministic testing. A serialized database transaction reserves budget before invoking the adapter: transcription costs rounded-up audio seconds; synthesis costs input characters. Failed and timed-out calls retain their reservations. Jobs use 60-second leases. Expired jobs fail without automatically repeating an uncertain provider call. Consent, feature availability and staff scope are checked before and after provider work. Withdrawn consent discards late output. Run the existing support worker to process jobs after root integration.

Deployment limitations: this is asynchronous message transcription/read-aloud, not live speech streaming. Microphone recording needs a secure browser context and Web Audio support. The compatibility recorder uses ScriptProcessorNode; a future AudioWorklet upgrade can preserve the same WAV protocol. Recording and playback are functional without an external speech provider; transcription/synthesis require an operator-provided conforming adapter. No real-provider validation has been claimed.
