## 二、任务 A：本地一键启动与演示数据（最优先）

目的：我能在自己的 Mac 上随时启动系统，按测试清单测试客户场景和编辑场景。

1. **一键启动**：增加 `npm run local:start`，同时提供一个 Mac 上可以双击运行的 `start.command`。依次完成：
   - 检查 Node 版本；
   - 检查 PostgreSQL（支持 Homebrew 的 postgresql@15 或 @16）；没有安装的话，用中文提示安装命令后退出；
   - 初始化数据库、执行迁移、载入演示数据（已载入则跳过）；
   - 启动网站，并自动打开浏览器。
     后台任务进程默认不启动。
2. **停止与重置**：
   - `npm run local:stop`：停止网站和数据库；
   - `npm run local:reset`：先把当前本地库备份到 .local/backups，再恢复到初始演示状态。如果 DATABASE_URL 不是本地专用实例，必须拒绝执行。
3. **演示数据**：必须包含**已发布**的内容，让客户场景可以完整测试：
   - 首页文案；
   - 至少 3 个服务页（展会陪同、看厂、接机）；
   - 关于我们、联系方式、隐私说明、服务边界的**演示占位版**，每页醒目标注"演示内容，非真实公司信息"；
   - 至少 5 篇指南；
   - 至少 3 个展会；
   - 免签政策：使用虚构国家，覆盖单方面免签、240 小时过境、已过期、截止日之后"尚未确认"四种情况；
   - 后台数据：咨询至少 5 条（覆盖不同状态）、服务商申请至少 3 条、服务单和报价至少 2 份（其中至少 1 份待审核）；另外各留一条待审核的政策和指南。
     所有演示数据都要标记为演示，只在 APP_ENV=local 时允许载入；任何非本地环境都拒绝执行。
4. **本地默认开关**：免签查询工具开启；咨询表单为本地模式（保存但不发邮件）；AI、邮件、语音、通话、客服、客户中心关闭。
5. **测试账号**：管理员、主管（报价和内容审核人）、运营、第二审核人，各一个，再加一个"新人"运营账号，供测试清单里的"新人测试"使用。账号和密码写入 `.local/test-accounts.txt`（已在 .gitignore 中忽略）。
6. **中文《本地测试指南》**（docs/local-testing-guide.md），控制在一到两页：
   - 怎么启动、关闭、重置；
   - 每个账号能做什么；
   - 目前可以测哪些场景（按测试清单编号 C1–C10、E1–E10 列出，并注明哪些要等后续任务完成）；
   - 发现问题怎么记录：截图 + 操作步骤 + 期望的样子。
7. **验收**：按指南操作，在一台干净的 Mac 上 10 分钟内能启动；重复执行启动脚本不会出错；CI 不受影响。PR 描述里附首页、服务页、免签工具、咨询表单在手机尺寸下的截图。

## 附录 2：员工工作台与个人业绩看板（任务 G）

1. **"我的今天"工作台**：作为登录后的首页，按截止时间列出当前员工的待办：今天到期的咨询跟进、待回复的新咨询、待自己审核的内容和报价、政策和内容的复核任务。每条待办写明下一步具体做什么，并直接链接到操作页面。
2. **回复模板库**：后台维护中英文模板，分为咨询回复、报价说明、服务确认三类；处理咨询时可以插入模板，修改后再发送或复制。
3. **政策批量导入**：导入《首批免签政策录入与核实模板》格式的 CSV。生成的记录一律是草稿，并记录导入人；先逐行校验，出错时逐行用业务语言说明原因。（如果任务 C 之后数据结构有变化，按新结构执行。）
4. **每日摘要**：员工可以选择把非紧急通知合并成每天早上一封站内摘要；紧急通知照常即时发送。
5. **报错提示**：后台所有校验错误改成业务语言，告诉用户怎么改；字段名和帮助说明避免技术术语。
6. **个人业绩看板**：管理员可以看所有人，员工只能看自己。按月统计每个负责人的：
   - 首次响应时长中位数
   - 按时跟进率
   - 有效投诉数
   - 内容按计划发布数
   - 审核退回率
   - 发布后纠错次数
   - 逾期复核待办数
   - 审核人的处理时长
     按后台配置的权重和目标值，自动算出月度评分卡。可以导出 CSV，沿用现有的权限、审计和防公式注入规则。
7. ⏸ "有效投诉"和"发布后纠错"的判定口径（由谁标记、能否申诉），先提出方案，由我确认后再开发统计。

## 附录 3：客户端问题修复（任务 D）

以下问题来自 2026-11-08 的本地客户视角审查，基于合并后的 main，手机尺寸 390 像素宽。

1. **空内容的显示**：
   - 知识中心不显示没有已发布内容的分类（现在显示八个"0 published"）；
   - 菜单自动隐藏没有已发布内容的栏目；
   - 不要出现指向未发布服务页的链接（避免点进 404）。
2. **页脚统一**：所有页面都使用完整页脚（导航、联系、品牌语）。从页脚去掉"Published content data for agents"，llms.txt 只保留在 robots 和 sitemap 中。
3. **顶部子导航**："Find providers · Hua service projects"只在服务和服务商相关的页面显示。
4. **免签工具入口**：功能开启时，首页首屏和菜单里都要有醒目的入口。
5. **信任信息区块**：首页显示公司名称、所在地和联系方式，内容来自后台配置。**没有配置时不显示，也不能用占位文字冒充真实信息。**
6. **展会页（手机）**：筛选条件收进一个"筛选"按钮，默认先显示即将举办的展会；"月份"改为下拉选择。
7. **客服页**：客服功能关闭时，/support 整页不显示（返回 404 或跳转到联系页）。功能开启时，文案改成客户看得懂的白话，例如把"This browser credential grants conversation access"换成普通说明。
8. **真实公司信息**：隐私说明、关于我们、联系方式、服务边界的真实内容由我和律师提供。你只负责确保：信息没有配置时，页面上不出现任何虚构的公司信息。

**验收**：PR 描述中附手机（390 像素）和桌面（1440 像素）的修改前后对比截图；首页、菜单、知识中心、展会、客服页都要覆盖。
