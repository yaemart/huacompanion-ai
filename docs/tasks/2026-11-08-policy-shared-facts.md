## 已明确的行为

1. 同一政策组只有一个正在生效的不可变事实版本。事实经一次审核发布，中英文页面同时采用该版本，不能分别发布成不同事实版本。
2. 中文、英文公开说明分别编辑、审核、发布，互不阻塞；说明发布不能改变事实版本。
3. 事实新版发布后，两种语言的说明都自动标为“待复核”。该语言复核通过之前，公开页面只显示事实，隐藏旧说明，并在后台待办提醒。
4. 说明中出现日期、天数、小时数时，后台提示建议移到事实字段。提示不自动修改文案、不代替审核，也不阻止保存。
5. 用户确认目前未部署、没有真实政策，现有政策均为虚构测试数据。本次备份后清空这些测试政策，在新结构重建，不做人工配对和新旧对照迁移。旧正式版本不自动改变、差异人工配对的无损迁移步骤保留，标注为日后有真实数据时使用。

此前“两语各自发布事实，容许暂时不同版本”的建议已撤销。不采用保存两份事实后互相复制的方式，避免内容与审核状态漂移；不启用影响其他模块的全局多语言改造。

## 数据结构与公开读取

以下是建议的逻辑对象，具体集合名和迁移DDL在对应实现计划中制定，本文已获批不代表这些步骤已经执行。

| 对象           | 内容与约束                                                                                                                |
| -------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 政策组         | 稳定组ID、业务contentKey、唯一正式事实版本引用；国家和类型相同不意味着必须合为同组                                        |
| 事实工作稿     | 国家代码及中英名称、类型、停留数值和单位、生效/截止日、口岸条件、官方来源、核实人及日期、内部核实备注；独立修订和审核状态 |
| 不可变事实版本 | 审核发布时复制完整事实及审核记录；发布后不就地改写，内部核实备注和员工身份仍不得公开                                      |
| 语言说明工作稿 | 组ID、locale、公开说明、所依据的事实版本、修改人和审核状态；沿用相应语言的标题和网址                                      |
| 不可变说明版本 | 审核后的文案、locale、精确事实版本引用和审核记录；每个语言分别维护正式引用及待复核状态                                    |
| 后台待办       | 按政策组、语言、事实版本幂等生成说明复核任务；沿用现有板块权限及失效负责人处理规则，不发送外部邮件                        |

公开读取在同一次请求中取得政策组的唯一正式事实版本，再选择当前语言已审核且引用该事实版本的说明。引用不一致或状态待复核时只返回事实，不能退回旧事实、旧说明或直接读取可变工作稿。前端隐藏之外，服务端公开投影也必须排除失效说明。

统一发布指两语共用一个生效指针，在一次事务中切换，而非分别更新两套事实快照。已打开的旧页面或切换前发出的请求可能显示旧结果，但切换后新请求不得因语言不同选择旧指针。公开读取需一致处理两语缓存失效，不得保留可被新请求命中的单语旧事实缓存；优先直接读取统一生效指针，不能依靠两次各自独立的缓存刷新维持一致。

口岸仍是一份共用事实文本，需要语言解释的文字放对应说明；本轮不建设口岸库、来源库。停留单位明确为天或小时。旧`maxStayDays`不能一律乘24：现有过境查询按类型固定显示240小时，转换须按旧契约逐项核对。

## 审核、发布与并发

- 事实编辑、提交、审核发布为一条独立流程；一次批准只覆盖送审时的精确事实修订，不再要求两语分别批准同一事实。现有编辑/审核角色、板块范围、双人审核、禁止自审及管理员例外须填原因的规则保留，不增加自动批准路径。
- 事实发布事务同时：写入不可变正式版本、切换唯一生效引用、将两语说明标为待复核、更新复核待办并写审计。任一步失败全部回滚。第一版发布时尚无说明的语言同样提醒补充或复核，不生成虚构译文。
- 说明复核针对当前正式事实版本。每种语言独立提交、审核发布；另一语缺失或退回不阻塞。复核通过后显示该说明并完成对应待办，旧说明快照只保留历史用途。
- 提交说明前及批准事务内均核对事实版本；审核期间事实又更新时拒绝过时批准，要求按新事实重新复核。不能把旧审批自动挪到新版本，也不能清空新版待办。
- 自审检查覆盖本次审批对象的实际编辑参与人，不能通过另建语言副本绕过。事实和说明的审批记录分开，审批对象、版本、操作者、原因均可追溯。
- 修改事实工作稿不影响公开事实和说明；只有正式发布新事实才使说明待复核。恢复历史事实或说明只能生成新工作稿，再走相应审核，不直接回写生效引用。
- 沿用现有事务和冲突校验；同组事实发布与说明发布必须串行检查修订，防止并发时重新露出旧说明。暂不借本任务改变全局锁策略。

说明状态示例：事实第1版、中文说明第2版和英文说明第1版均可见；事实第2版发布后，两语都只显示事实；中文复核完成后仅恢复中文说明，英文继续隐藏并保留待办。

## 数值提示

编辑器对中英文常见日期及停留表达做本地规则检测，例如`2027-01-01`、`2027年1月1日`、`30天`、`240小时`、`30 days`和`240 hours`，在说明旁提示“建议将日期、停留天数或小时数放入事实字段，以免事实更新后说明不一致”。

这是辅助提示，可能误报或漏报，不宣称语义校验；不调用AI、不联网、不静默改写、不放宽人工审核。提示文本和检测样例纳入测试。

## 本次迁移：备份后重建虚构测试政策（本机已按清单完成）

适用前提是本机未部署且政策全为虚构测试数据。只在第1条实现PR执行，不在当前文档PR清理。

1. 暂停网站及worker写入，重新清点政策记录、政策类工作稿/正式快照/历史、政策复核待办及引用。生成明确的政策ID/关联清单；若发现真实政策、来源不明的数据或已部署环境，则停止清理，改用下节真实数据流程，不能靠测试开关强行执行。
2. 数据库与图片配套备份到忽略目录，核对备份可读及恢复结果；先在隔离克隆演练新结构和清理。备份保留原测试历史，恢复时使用独立实例，避免覆盖其他本地内容。
3. 按明确清单清空虚构政策及其对应的政策工作稿、正式快照、版本和失效待办关联。不得全库重置，不按宽泛条件删除共用内容表，也不删除非政策指南、报价、客户、员工或图片。涉及指南中的旧政策引用须列出并安全处理为尚未确认，不能删除指南正文或留下能读到旧事实的悬空引用；清理操作本身留审计记录。
4. 应用新结构，在新结构上重建最小虚构测试数据，覆盖中英共用事实、说明缺失/待复核、天/小时、日期边界、双人审核及管理员例外。数据显式标为测试，虚构国家限制仍只在测试环境允许，不写入真实政策结论。
5. 本次不编写或执行人工配对、新旧政策映射与逐条公开输出对照迁移。清理和重建应可重试、范围受保护，失败不得留下半套可公开结构；失败时停止新读取，按已演练的配套备份恢复方案处理。
6. 验证新结构的单元、迁移、权限、并发、发布/说明复核和公开读取；对非政策业务记录与媒体核对清理前后指纹，确认没有扩大删除范围。新测试数据不自动批准发布，发布行为仅通过隔离验收中的明确人工/测试审批执行。

## 日后有真实数据时使用：无损迁移（本次不实施）

以下保留原方案作为未来参考，不能混入本次虚构数据重建范围。届时须重新清点并审阅适配后的迁移计划；不得拿本次测试数据清理授权删除真实数据。

1. 暂停写入，数据库与图片配套备份；在独立克隆上先执行只读清点。记录原始记录、工作稿、历史及正式快照和引用，按实际表清单校验原字段及媒体指纹。
2. 只增加新结构和可空关联，保留旧ID、policyKey、policyRef、历史快照及原数据。采用经确认的映射清单和差异报告，必要时另行评估配对工具，不自动猜测事实语义。
3. 同contentKey中英各唯一且事实完全一致时可建议配对；同国同类型但日期、来源、核实信息、口岸等不同，或引用缺失时，必须列出差异供人工选定。不能推测哪个版本正确，也不能把一半语言先切换。
4. 经人工确认后创建政策组、事实工作稿和语言说明工作稿，保留旧ID到新ID的映射及原说明。未确认的组完整保留旧结构，不自动改动其已发布版本。缺少另一语言不补造翻译。
5. 迁移不等于审核或发布，不修改旧正式快照，也不把历史审批转换成对新事实/说明的批准。新结构启用须有明确的事实审核发布动作；组切换时两语一起使用新事实，原说明未按该版本复核前一律隐藏。未迁移的组保持原状，但新读取的整体启用门禁必须确认目标范围内所有正式政策已解决配对和审核问题；不能用旧语言快照作为新政策组的回退来源，不能为过门禁自动下架旧政策。
6. 迁移按组事务处理且可重复运行；冲突整组回滚，不能重复创建映射。保留原始差异和人工决定记录，不因“只有测试数据”而删除旧历史。
7. 克隆验证：旧正式快照及原字段指纹不变、关联不丢、重复执行无新增、失败回滚完整；新增发布后两语事实一致，说明按复核状态显示。当前真实政策尚未录入不能代替部署前再清点。
8. 回退先停写并保留新数据。仅在新数据能无损表示时允许旧程序接管，否则拒绝破坏性down；从配套备份恢复到新实例核验后再切换，不直接覆盖旧库或删除新版本。

## 实施验收与停止点

- 一次事实审核发布同时切换两语；其中一语没有说明或正在退回也不阻塞事实发布。
- 发布失败全回滚；并发事实发布/说明批准不能造成两语事实分叉或旧说明复活。
- 事实更新后两语说明服务端均隐藏、待办幂等；一语重新审核只恢复该语，另一语保持待复核。
- 自审拒绝、板块越权拒绝、管理员无原因拒绝及历史恢复仍须审核；公开接口不得泄露内部备注和员工信息。
- 日期/天/小时提示覆盖中英样例及误报处理；保存原文不变。
- 本次验证配套备份可恢复、清理仅命中虚构政策关联、非政策记录/媒体指纹不变、重建幂等、失败保护及新结构读写；不执行人工配对/新旧对照迁移。日后有真实数据时再验证前述无损迁移要求。桌面与手机验收，截图放PR附件。
- 每次提交前`npm run check`和相关集成通过，lint警告不增加；实际结果写入`docs/progress.md`。
