# 任务 G · 有效投诉与发布后纠错口径

已确认（2026-11-15）。基于任务 G 的停止点、岗位 SOP 和 PR #63 合并后的 `main`（`7f46e50`）。客服满意度、服务单记录、内容版本和发布审计可以提供证据。由员工登记、具备权限的人员确认，并允许本人申请复核。直接按差评或重新发布次数计算，容易把服务偏好和正常更新算成绩效事件。

## 有效投诉

- **成立条件**。客户提出了具体服务问题，服务单、报价、沟通或履约记录能证明实际处理违反已确认的承诺或业务标准。例如已约定的服务未交付、已经确认的费用与实际收费不符。没有具体事实的低评分、超出约定范围的请求和重复催问，留作服务反馈。证据不足的记录待补充。
- **登记和确认**。运营按 SOP 当天回复客户，在服务单售后登记。主管在现有团队权限内确认，涉及跨团队或主管本人时由未涉事管理员处理。判定须填写理由，引用可核对的记录，并区分华伴责任、供应商责任或无法归责。同一服务问题经邮件、电话和聊天反复反馈，形成一件投诉。
- **个人归属**。有证据表明某员工在事发时负责该环节，并有明确过失，才计入该员工的指标。转交后接手、登记投诉或负责善后的员工按其实际行为判断。供应商单方责任仍可记为已确认的服务投诉，个人指标保持零计数。

## 发布后纠错

- **成立条件**。已经公开的版本在发布时存在可核实的实质错误，例如当时有效的政策日期、适用条件或服务价格写错。正常排版、语气优化、例行复核和发布以后才发生的政策变化归入内容维护。发现错误后按 SOP 及时处理公开内容，计数确认可以随后完成。
- **登记和确认**。有权查看内容的发现人登记，关联当时的正式版本、合理可得的来源、错误字段和修正记录。由有对应板块权限且未参与原版本的审核人确认，必要时由未涉事管理员确认。同一份中英共用政策事实的同一个错误只登记一次。独立存在的翻译错误按对应语言的正式版本登记。下架、补稿和再次发布共用同一条纠错记录。
- **个人归属**。核实、录入和审核各自依据当时的职责和可用证据。编辑和审核都有明确证据时，同一事件可分别归到各自的责任环节，同一员工最多计一次。审核人可核对自己审过的版本发生了哪些已确认纠错。个人计数只采纳有明确责任的判定，主动发现和修复的行为本身可以如实记录。

## 申诉和月报

- 员工收到站内判定后，可在 7 个自然日内申请一次复核，从通知后的次日开始按北京时间计算。员工看自己的判定、理由和去隐私摘要。证据原文按现有记录权限访问。看板及 CSV 保持管理员可看全部、员工只看本人的范围。
- 复核人须有相应权限，且不同于原判定人和涉事人员。复核结果可维持、撤销或更正责任归属，须记录理由。无人可独立复核时保留待复核状态。初判、通知、申诉和复核都记录操作者与时间。
- 待确认、申诉期内和申诉复核中的事件显示为待定。申诉期结束且无申诉，或复核作出结论后，才计入首次确认所在的北京时间自然月。跨月复核可更正原月，导出注明统计截至时间。同一事件若同时有投诉和纠错，关联两条证据，评分如何处理重复扣分留到权重方案确认。
- 按 SOP，试行前三个月记录指标和复核结果，暂缓扣分。

确认口径后，先交付登记、确认、申诉和权限测试，验证真实记录如何产生，再交付月报、评分与导出。
