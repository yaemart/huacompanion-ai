# 本地一键演示：小PR实施方案

2026-11-08。用户最新目标：先本地做到客户友好、编辑友好，由用户亲测后才考虑部署；11月30日不再是上线日期。

## 推荐方式

使用本机已有Node24.22.1与PostgreSQL15，新建独立演示实例和数据库。复用现有Payload后台与网站，不新增业务页面或外部服务。本机原生PostgreSQL15工具已具备，推荐直接复用。Docker命令也已存在，但容器方式还依赖守护进程；本次不新增容器启动依赖。

- 提供一条启动命令及Mac可双击的.command入口，自动检查运行环境、启动演示数据库、首次装入数据、启动网站并显示官网与后台入口。
- 演示库、密钥、账号凭据及图片放独立的忽略目录.local/demo；不读取或覆盖现有业务.env、数据库及图片。Next开发输出也隔离，避免与当前3000网站冲突。
- 网站拟使用127.0.0.1:3100，数据库拟使用127.0.0.1:55442，端口被其他程序占用时说明原因，不停掉无关进程。官网和后台由同一网站进程提供。
- 首次初始化自动装入每类若干条明确标为虚构的政策、指南、展会、咨询和报价，覆盖草稿/待审核及已发布示例；示例发布只发生在受保护的独立演示库，沿用真实审核服务由不同测试账号完成，不开放业务发布权限。
- 后续普通启动保留用户的测试修改，不重复插入或自动重置。中断初始化可以安全重试；已有演示数据不因代码更新被静默删除。
- 提供关闭命令/双击入口，只关闭本工具启动的进程；提供恢复初始状态入口，明确确认后仅重置有演示标记且地址/库名匹配的演示库。可重建新演示库，不操作原本地库。

## 四个测试账号

本机随机生成密码，写入.local/demo中的权限受限凭据文件，启动后提示打开位置；不把密码放Git、截图或日志。

| 账号   | 现有权限配置                                                         |
| ------ | -------------------------------------------------------------------- |
| 管理员 | 管理演示员工与设置、完整测试数据；自审仍按当前规则填写例外原因       |
| 主管   | 管理演示团队业务、查看成本；不凭主管身份自动获得内容审核权           |
| 运营   | 本人且同团队咨询/报价权限；兼任内容编辑，仅授权政策、指南、展会      |
| 审核人 | 授权政策、指南、展会审核；禁止审核自己的编辑，不额外获得业务成本权限 |

报价分项和所有报价二审仍未实现，此小PR不提前实现；指南明确当前可验与后续待验，不能为演示先改权限或伪造未来功能。

## 一页中文指南与验收

一页说明：启动、关闭、重置、账号能力和五类示例入口；问题按“账号、页面、操作步骤、预期/实际、截图”记录，不附密码或客户资料。用户每个实现PR合并后按此指南亲测。

开发检查包括完整check、首次启动/重复启动/关闭/重置后恢复演示、占用端口与非演示库重置拒绝、四账号登录及代表性权限/双人审核；核对原本地数据和图片未变。截图放PR附件，不提交Git。四账号、数据仅用于本机，不部署、不购买、不启动外发worker。
