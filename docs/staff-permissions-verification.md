# 员工权限第一批：配置与验收

本地实施日期：2026-10-29。此说明对应第一批权限，不表示已部署 Replit 或云环境。

## 角色

| 角色 | 业务资料 | 内容工作台 | 授权管理 |
| --- | --- | --- | --- |
| 管理员 | 全部 | 全部板块；本人参与内容的审核须填写例外原因 | 员工、团队、角色、板块、审计 |
| 业务主管 | 本团队；可分配同团队运营负责人 | 需兼任内容角色并授权板块 | 不可改团队或员工权限 |
| 客服运营 | 本团队且本人负责的咨询与私有服务商资料 | 需兼任内容角色并授权板块 | 无 |
| 内容编辑 | 无业务私有资料 | 授权板块起草、修改、提交及 AI 草稿操作 | 无 |
| 内容审核 | 无业务私有资料 | 授权板块阅读、审核、退回和下架 | 无 |

员工可配置附加角色；内容板块仍需单独授权。新员工默认没有内容板块授权。内容的已知编辑者或提交者不能审核该内容，兼任编辑与审核也不能绕过。管理员例外需要原因并留下审计记录。

## 开始使用

1. 管理员进入 `/admin/collections/teams` 创建实际业务团队。
2. 在 `/admin/collections/staff` 配置员工主角色、附加角色、团队、启用状态及内容板块。
3. 管理员为咨询和私有服务商记录分配团队，再由管理员或该团队主管分配同团队运营负责人。
4. 内容编辑在 `/content-center` 创建并提交草稿，独立审核人员审核发布。
5. 离职或暂时停止协作时停用账号；无需删除员工及其历史记录。

旧业务资料不会被自动分给任何团队。未分配团队的记录仅管理员可见。旧管理员与编辑的原有内容板块访问已迁移保留。

## 保护范围

- 权限由服务端执行，覆盖后台、原生接口、自定义内容接口、历史、预览、素材及 AI 草稿任务。
- 运营不可更改原始客户提交、来源和同意信息；团队与负责人变更受约束。
- 业务历史版本仅管理员读取，防止记录转交后泄露历史联系方式。
- 待审核内容不能继续修改；未审核修改不会覆盖已发布内容。
- 私有素材限制访问；被正式发布内容引用的素材可公开读取。
- 员工角色、团队、板块或启用状态变化时撤销会话；停用员工不能登录。
- 工作台在重新取得焦点和操作被拒绝时刷新权限。已看过或下载的信息无法追溯抹除。
- 审计记录不可由普通员工修改或删除；员工采用停用方式保留历史。
