# 阶段2：邮件订阅分步设计（待逐步实施）

目的：让访客自愿订阅政策更新、展会提醒、采购指南或单个展会。2.2a 已实现私有订阅数据和确认凭证。2.2b 已接入确认和退订链接、公开提交及确认邮件入队。

## 交付顺序

每一步从合并后的最新 main 开始，独立可合并、默认关闭，前一步合并后再开下一步。业务改动超过 400 行时继续拆分。

| 步骤                | 复用与增量                                                                                              | 验证后再交付                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 2.1 防滥用复核      | 已有客户端/全站限流、认证代理头及honeypot；核对所有新订阅入口复用，不为已完成项开空PR                   | 伪造IP头无效、单客户端不挡其他客户、全站防线及蜜罐；仅保存限流摘要，不新增原始IP记录    |
| 2.2a 数据与确认凭证 | 订阅者、主题和确认状态；密码学随机令牌只存摘要、有效期及版本，安全迁移                                  | 未确认不生效、令牌过期/重放/跨用途拒绝、迁移保留原数据、匿名不能读取邮箱                |
| 2.2b 单次确认及退订 | 沿用已有Resend事务适配器与可靠任务机制，公开提交统一回应；同邮箱冷却/日上限，失败和不确定发送不假称成功 | 重试幂等、同邮箱洪泛、确认/退订顺序与再订阅、关闭后无发送；确认及退订不依赖登录         |
| 2.3 公开组件        | 中英文主题预设、明确同意与隐私版本；只有开关/邮件/隐私配置齐备才显示                                    | 无配置整体隐藏、跨域/蜜罐/重复提交、键盘/手机、取消不订阅；真实送达待账号               |
| 2.4 后台管理与导出  | 主题订阅/退订数量，权限范围和审计导出，复用BOM/公式转义                                                 | 匿名/未授权/撤权不能读邮箱或导出，导出无令牌/内部字段，审计记录数量与筛选，公式注入转义 |

2.2b 的邮件发送、可靠重试和邮件客户端一键退订留在下一批。2.3 和 2.4 待逐步实施。

## 2.2a 实施记录

- 同一个规范化邮箱和主题共用一条订阅，单场展会主题使用展会内容编号。待确认记录不生效，确认后再次提交同主题沿用既有确认。
- 确认凭证为 32 字节随机值，按用途计算 SHA-256 摘要，存 24 小时有效期、同意版本及核销时间。重新签发会提高同意版本，原凭证失效。确认、核销和并发防重放共用数据库事务。
- 两个 Payload 集合关闭直连端点和默认集合权限。2.2a 通过服务器内部服务和临时数据库亲测。公开入口、退订动作和发送开关在后续批次接入。 [本地亲测](subscription-data-summary.md)

## 2.2b 第一批实施记录

- 确认和退订共用原子核销流程，分别签发 24 小时和 365 天凭证。退订可取消已确认或待确认的单一主题。再次同意时版本递增，旧凭证随即失效。
- 匿名打开链接时仅显示中英文操作页。浏览器在地址栏移除凭证片段，明确点击后以同源 POST 提交，关闭缓存和索引。确认及退订页面由 `SUBSCRIPTIONS_ENABLED` 控制，默认关闭。
- 2.2b 的下一批接入公开提交、同邮箱冷却和上限、单封邮件可靠发送及邮件客户端一键退订头。邮件暂停使用既有发送开关，以保留已启用的退订链接。 [本地亲测](subscription-links-summary.md)
- 发送批次使用直达事务链接，关闭邮件供应商点击跟踪，避免链接片段被重写到第三方请求地址。后续可发送的邮件需包含当前有效的退订方式，覆盖存续时间超过 365 天的订阅。

## 2.2b 公开提交与入队

- `POST /api/subscriptions/request` 验证同源、语言、明确同意和当前隐私版本；单场展会验证其公开版本。复用可信网关、蜜罐和客户端及全站限流，订阅使用独立键空间。非本机配置须提供可信网关。
- 同一规范化邮箱跨主题共用入队额度，15 分钟一次，滚动 24 小时最多五次。额度、已确认记录、蜜罐和正常请求统一回执。待确认记录和私有邮件任务同事务写入，正常入队后复核已提交的唯一键才返回接收回执。
- `SUBSCRIPTION_REQUESTS_ENABLED` 默认关闭，与 `SUBSCRIPTIONS_ENABLED`、邮件环境和后台邮件开关配合。单独关新请求时，可继续使用既有链接。
- 下一批 worker 依据任务唯一键和同意版本检查当前收件权限，保留队列预约记录，并在发送时再次核对同邮箱实际发送间隔。模拟确认邮件、可靠重试和客户端一键退订在下一批验收。 [本地亲测](subscription-submission-summary.md)

## 约束与建议默认值

- 不增加依赖或新邮件服务，先复用现有事务邮件边界；新SUBSCRIPTIONS_ENABLED建议默认false，并同时检查既有邮件开关、已验证发件域名及隐私版本。后台开关不能绕过未配置状态。本地只用注入适配器，不发真实邮件。
- 必要字段：规范化邮箱、语言、主题/单展会、同意时间、隐私版本、来源页面、合作方编号（可空）、状态/确认/退订时间；不记录IP、国籍、行程日期或原始工具输入。外部返回不泄露邮箱是否已存在。
- 建议确认凭证24小时过期；同邮箱确认发送15分钟冷却、每天最多5次，再叠加现有限流。数值实施时作为显式产品默认值复核；不能为测试而放宽。
- 工具“发到我的邮箱”拟只发送用户明确选择的公开政策资料标识和语言，服务器重读当时仍发布的资料；不上传原国籍/入境日期，也不把邮件称为入境资格结论。提交前说明将发送哪些资料及订阅哪个主题。
- 邮件包含退订入口；邮箱客户端一键退订与网页POST确认要防链接预取误操作。令牌不进入日志、导出或审计正文，旧令牌不能撤销新的明确同意。
- 权限不自动扩给全部运营：建议先仅管理员有邮箱及导出权限；若需要主管/团队范围，必须先明确分配规则和显式授权并补测试。不能把客户咨询权限等同于所有订阅邮箱权限。
- 真实邮件送达及隐私说明主体需用户提供；这不妨碍先做默认关闭的隔离实现。WhatsApp仅在2.5配置链接，非本轮接入。

## 停止点C保持

群发仍未选方案：后续比较“同步外部邮件工具”和“后台主管测试发送/幂等/限速”。用户选定前不实现同步群发、按主题批量发送或展会定时实发。确认邮件仅限订阅者自己的单次请求，不意味着获准群发。
