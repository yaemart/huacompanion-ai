# 阶段2：邮件订阅分步设计（待逐步实施）

目的：让访客自愿订阅政策更新、展会提醒、采购指南或单个展会。这里只准备设计，未新增数据库、公开入口、发送器或群发。

## 交付顺序

PR19由用户审阅合并后，fetch最新main再开始；每一步独立可合并、默认关闭，前一步合并后再开下一步。业务改动超过400行时继续拆分，不能将所有订阅功能叠在同一个分支。

| 步骤                | 复用与增量                                                                                              | 验证后再交付                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 2.1 防滥用复核      | 已有客户端/全站限流、认证代理头及honeypot；核对所有新订阅入口复用，不为已完成项开空PR                   | 伪造IP头无效、单客户端不挡其他客户、全站防线及蜜罐；仅保存限流摘要，不新增原始IP记录    |
| 2.2a 数据与确认凭证 | 订阅者、主题和确认状态；密码学随机令牌只存摘要、有效期及版本，安全迁移                                  | 未确认不生效、令牌过期/重放/跨用途拒绝、迁移保留原数据、匿名不能读取邮箱                |
| 2.2b 单次确认及退订 | 沿用已有Resend事务适配器与可靠任务机制，公开提交统一回应；同邮箱冷却/日上限，失败和不确定发送不假称成功 | 重试幂等、同邮箱洪泛、确认/退订顺序与再订阅、关闭后无发送；确认及退订不依赖登录         |
| 2.3 公开组件        | 中英文主题预设、明确同意与隐私版本；只有开关/邮件/隐私配置齐备才显示                                    | 无配置整体隐藏、跨域/蜜罐/重复提交、键盘/手机、取消不订阅；真实送达待账号               |
| 2.4 后台管理与导出  | 主题订阅/退订数量，权限范围和审计导出，复用BOM/公式转义                                                 | 匿名/未授权/撤权不能读邮箱或导出，导出无令牌/内部字段，审计记录数量与筛选，公式注入转义 |

上述是拆分建议，实施每一步前根据当时main及批准范围形成小任务；2.2–2.4仍未开发，不写成已完成。

## 约束与建议默认值

- 不增加依赖或新邮件服务，先复用现有事务邮件边界；新SUBSCRIPTIONS_ENABLED建议默认false，并同时检查既有邮件开关、已验证发件域名及隐私版本。后台开关不能绕过未配置状态。本地只用注入适配器，不发真实邮件。
- 必要字段：规范化邮箱、语言、主题/单展会、同意时间、隐私版本、来源页面、合作方编号（可空）、状态/确认/退订时间；不记录IP、国籍、行程日期或原始工具输入。外部返回不泄露邮箱是否已存在。
- 建议确认凭证24小时过期；同邮箱确认发送15分钟冷却、每天最多5次，再叠加现有限流。数值实施时作为显式产品默认值复核；不能为测试而放宽。
- 工具“发到我的邮箱”拟只发送用户明确选择的公开政策资料标识和语言，服务器重读当时仍发布的资料；不上传原国籍/入境日期，也不把邮件称为入境资格结论。提交前说明将发送哪些资料及订阅哪个主题。
- 邮件包含退订入口；邮箱客户端一键退订与网页POST确认要防链接预取误操作。令牌不进入日志、导出或审计正文，旧令牌不能撤销新的明确同意。
- 权限不自动扩给全部运营：建议先仅管理员有邮箱及导出权限；若需要主管/团队范围，必须先明确分配规则和显式授权并补测试。不能把客户咨询权限等同于所有订阅邮箱权限。
- 真实邮件送达及隐私说明主体需用户提供；这不妨碍先做默认关闭的隔离实现。WhatsApp仅在2.5配置链接，非本轮接入。

## 停止点C保持

群发仍未选方案：后续比较“同步外部邮件工具”和“后台主管测试发送/幂等/限速”。用户选定前不实现同步群发、按主题批量发送或展会定时实发。确认邮件仅限订阅者自己的单次请求，不意味着获准群发。
