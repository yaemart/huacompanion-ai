# 群发任务：当前资格复核与持久取消

本批先完成本地调度的前置服务：检查已经冻结的任务是否仍符合原同意和收件资料，把无效任务记为取消，并保留原因和时间。冻结时的名单与人数保持原样，后来订阅的人不会补入。

## 本批可以验证什么

- 退订、未确认、隐私版本失效或被较新记录取代：取消原任务。
- 当前同意版本与冻结时不同：取消原任务，不能把新的同意套到旧任务上。
- 邮箱或语言变化：取消原任务，不擅自换地址或语言。
- 已取消任务不会因为重新订阅、重新确认或资料改回而恢复。
- 多次或并发复核不会重复取消同一任务。每次显式复核有审计，任务更新和审计一起提交；失败不留下部分取消。
- 仍要求获授权主管本人最新草稿、有效来源和模拟确认。越权、旧版本、配置变化及非本地环境拒绝。

## 怎么在本机验证

使用 Node 24.22.1，保持演示 PostgreSQL 运行，执行：

```sh
npm run test:subscriptions
```

命令在随机临时数据库中应用迁移并用虚构数据运行19组检查，退出后清理。最后应看到“PASS 冻结任务实时资格复核、持久取消、重订不复活、并发、权限及审计提交回滚”，正常结束。测试包含真实的本地确认→退订→复核→重订确认流程；这里的“确认”不代表发过真实邮件。失败时反馈命令、时间和错误，不附环境文件或密码。

本轮353项单元测试、类型及格式检查通过，lint445条既有警告未增加；19组订阅集成通过，一次独立只读复核无发现。本批没有新页面或按钮，不据此声称真人浏览器验收通过，也没有本批截图。

## 还没有做什么

剩余有效任务仍是不可发送的暂存状态。复核只反映查询当时的资格，实际投递仍须再读当前状态并处理并发。额度占用、任务租约、重试、拒发回执、改版续发及真实邮件未接入；现有单封邮件限额和队列未改。新的模拟确认可以用于取消无效任务，不因此替换冻结时的发送授权。
