# 华伴 Hua Companion：流量入口开发任务（分阶段、渐进交付）

本任务说明取代之前的"收敛与上线准备"和"补充任务（流量入口）"两份。以本文为准。

## 〇、背景与总原则

华伴近期的目标是建立面向外国人的流量入口："外国人在中国的第一站"。第一批用户是来华商务买家和短期游客，以英文为主。
策略：用免费工具和核实过的信息拉新，用邮件订阅留住用户，靠合作方（酒店、工厂、商会、社群）分发，再把用户导向咨询和服务。

### 工作规则（每一步都适用）

1. **一步一个 PR**。每一步都要能单独合并、单独上线。业务代码改动尽量控制在 400 行以内（迁移文件和测试不计）。超过的先拆分。
2. **合并前**：
   - `npm run check` 通过；
   - 新逻辑有单元测试；
   - 涉及权限、个人数据、导出的有集成测试；
   - 数据库迁移可以在已有数据上安全执行。
3. **新功能默认关闭**，由环境变量或后台开关控制。未配置时不显示，也不假装可用。
4. **新增任何依赖包、外部服务或付费账户之前，先问我。**
5. **数据不写死**。政策、展会、清单内容一律放在后台数据中，经现有审核发布流程上线，每条带来源链接和最后核实日期。
6. **只采集必要数据**。统计只记录事件和合作方编号，不记录 IP、不做跨站追踪，不接入广告追踪代码。
7. **代码格式**：一行一条语句；新代码和改动过的代码不使用 `any`。
8. **每一步完成后**，在 `docs/progress.md` 记录：改了什么、怎么验证的、手机和桌面截图、还剩什么。然后回复我。
9. **遇到标 ⏸ 的停止点，必须停下来等我确认。**

### 不做

论坛、评论区、自建社群、外卖或打车类交易、自动抓取政策或展会信息、AI 自动生成并直接发布内容、付费广告接入、商家地图（下一阶段再做）、支付。

## 阶段 0：准备（第 1 周）

**目标**：代码可读、可检查，试运行范围收窄到中英文。

- **0.1 格式化与检查**
  - 引入 Prettier 和 ESLint（typescript-eslint），行宽 100。
  - 用一个**只改格式**的提交格式化全仓库，提交说明写明"仅格式化"。
  - 增加 `npm run check`（lint + typecheck + 单元测试）和 GitHub Actions，在每次 push 和 PR 时运行。
  - 验收：格式化前后全部测试结果一致；源码中没有超过 200 字符的行（文案数据文件如有例外，列出清单）。
- **0.2 功能清单与语言范围**
  - 新建 `docs/feature-inventory.md`，列出每个模块的状态（已验证 / 已实现未验证 / 未实现）、开关位置、是否在试运行中开启。
  - 增加 `SITE_LOCALES`，默认 `en,zh`，英文为默认语言。其他语言保留代码，但不出现在语言切换器、sitemap 和 hreflang 中。
  - 确认客户中心、语音、通话、AI 报价草稿、AI 客服默认关闭。
- **0.3 依赖清理**
  - 执行不涉及破坏性变更的 `npm audit fix`，说明剩余漏洞是否只在开发依赖中。
  - 从 `dependencies` 中移除 `node` 包，改用 `engines` 字段和 `.nvmrc`。
- ⏸ **停止点 A**：
  1. 托管方案：给出一个推荐方案和一个备选方案，要求如下：
     - 境外托管，支持常驻的网站进程加两个后台任务进程；
     - 有持久化存储或对象存储、托管 PostgreSQL 及自动备份、HTTPS 和自定义域名；
     - 写明月费用估算，以及为什么适合非技术团队维护。
  2. 统计方案：自托管 Umami 或 Cloudflare Web Analytics，比较两者的优缺点。
     我确认之前，不购买任何服务，不接入任何统计代码。

## 阶段 1：免签查询工具与上线（目标 11 月 30 日前公开）

**目标**：第一个公开入口上线，赶上年底免签到期前的搜索高峰。

- **1.1 入境政策数据表**
  - 在后台新增"入境政策"集合，字段：
    - 国家（ISO 代码）
    - 政策类型：单方面免签 / 互免 / 240 小时过境 / 其他
    - 最长停留天数
    - 生效日、截止日（可为空）
    - 适用口岸或区域（过境类）
    - 官方来源链接、最后核实日期、核实人
    - 备注、状态（草稿 / 已发布）
  - 权限：编辑可以录入，审核人才能发布。修改保留版本历史。
  - 提供种子脚本，只生成**草稿**记录，由工作人员逐条核实后发布。
  - 验收：未发布的记录不出现在任何公开接口里；权限测试覆盖。
- **1.2 查询逻辑（纯函数）**
  - 输入国籍和入境日期，输出适用的入境方式、可停留天数、来源和核实日期。
  - 入境日期晚于截止日时，返回"该日期的政策尚未确认"，并附签证办理指引。不推测延期。
  - 单元测试覆盖：截止日当天及前后各一天、无截止日、多种政策叠加、过境与单方面免签的优先顺序、未知国籍。
- **1.3 公开页面** `/en/tools/china-visa-free-checker` 及中文版
  - 服务端渲染。没有 JavaScript 时，显示按国家排列的完整表格。
  - 查询在浏览器端完成，不向服务器发送用户的输入。
  - 每个结果显示来源链接和"最后核实日期"，页面上有免责说明。
  - 输出 FAQ 结构化数据。移动端 Lighthouse 性能和可访问性都 ≥ 90。
- **1.4 政策状态横幅**
  - 一个可嵌入任意内容页的组件，从政策表读取"即将到期 / 已延长 / 尚未确认"状态。
  - 用于"免签到期"专题文章。文章本身在内容中心编写。
- **1.5 到期提醒**
  - 政策截止日前 30 天和 7 天，在通知待办中自动生成核实任务。
- **1.6 搜索引擎基础**
  - 后台可编辑每页的 SEO 标题、描述和分享图。
  - 提供 `robots.txt`；sitemap 带中英文 hreflang。
  - 试运行环境默认 `noindex`，正式环境由环境变量开启收录。
  - 后台可配置 Google Search Console 的验证代码。
  - llms.txt 包含工具页。
- **1.7 部署**
  - 按我确认的托管方案提供 Dockerfile 或平台配置，部署网站和两个后台任务进程。
  - 配置 HTTPS、数据库每日备份，并完成一次实际的备份恢复演练。
  - 部署后验证：未登录账号和低权限账号都读不到后台和客户数据。
  - 冒烟测试通过后，才开启正式环境收录。
- ⏸ **停止点 B**：提交免签工具在手机和桌面上的截图、Lighthouse 得分和备份恢复记录。我确认后才公开。

## 阶段 2：邮件订阅与防滥用（目标 12 月 10 日）

**目标**：所有入口都能把访客变成订阅者。

- **2.1 按客户端限流**
  - 替换现有的全站共用表单限流：
    - 仅在配置了 `TRUSTED_PROXY` 时才信任对应的转发 IP 头，按客户端限流；
    - 全站总上限保留，作为最后一道防线；
    - 所有公开表单加隐藏字段（honeypot）拦截机器人。
  - 在部署文档中写明前置网关需要哪些配置。
- **2.2 订阅数据与双重确认**
  - 新增"订阅者"集合：邮箱、语言、订阅主题（政策更新 / 展会提醒 / 采购指南 / 单个展会）、同意时间、隐私版本、来源页面、合作方编号、状态。
  - 订阅流程：提交后发送确认邮件，点击确认才生效。每封邮件都有一键退订。
  - 同一邮箱的确认邮件发送频率有上限。
  - 邮件服务未配置时，订阅功能整体不显示。
- **2.3 订阅组件**
  - 可嵌入任意页面，可预设主题。
  - 工具结果页提供"发到我的邮箱"按钮，走同一套双重确认流程。
- **2.4 订阅者管理**
  - 后台按主题查看订阅和退订数量。
  - 可导出 CSV，要求：按权限过滤、写入审计记录、防 CSV 公式注入（以 `= + - @` 开头的单元格要转义）。
- **2.5 WhatsApp Channel**
  - 后台可配置频道链接，在订阅组件旁显示。这是纯配置，不做任何接入开发。
- ⏸ **停止点 C**：政策更新的群发方式，给我两个方案比较：
  1. 同步订阅者到外部邮件工具（例如 Resend Audiences）；
  2. 在后台内置一个"按主题发送"功能：需主管权限，先发测试邮件，带幂等保护和发送限速。
     我选定之前，不做任何群发。

## 阶段 4：转化与统计（12 月下旬）

- **4.1 转化区块**
  - 后台按内容类型和单个页面配置转化区块，例如展会页显示"预约展会陪同"，看厂指南显示"预约看厂一日陪同"。
  - 点击后进入现有的咨询表单，预填服务类别，并记录来源页面。
- **4.2 事件统计**
  - 按停止点 A 确认的方案接入统计，记录这几类事件：工具使用、订阅提交、订阅确认、转化区块点击、咨询提交。
  - 另外在本地建一张**按天汇总**的事件表，字段只有：日期、页面、事件类型、合作方编号、次数。不保存任何个人标识。
- **4.3 经营概览页**
  - 后台新增一页，按周显示：
    - 有效访客（用过工具、订阅过或点过转化区块的访客）
    - 新增订阅
    - 咨询数
    - 咨询按状态和类别的分布
    - 按来源页面和合作方的拆分
  - 普通运营只能看到自己权限范围内的咨询数据。
- **4.4 咨询导出**
  - 咨询和服务商申请导出 CSV（UTF-8 带 BOM，保证 Excel 打开中文不乱码），可按时间、状态、类别筛选。
  - 导出结果按导出人的权限过滤。供应商成本和内部备注默认不导出，只有管理员可以选择包含。
  - 防 CSV 公式注入，每次导出写入审计记录。

## 阶段 5：合作方归因与联合落地页（12 月—1 月）

- **5.1 渠道合作方**
  - 新增"渠道合作方"集合，与现有的服务商集合分开。字段：
    - 名称、类型（酒店 / 公寓 / 工厂 / 商会 / 社群 / 创作者）、联系人、分成规则说明、状态
    - 品牌使用授权：授权文件和授权日期
- **5.2 专属链接与二维码**
  - 为每个合作方生成带编号的链接，以及可下载的二维码（SVG 和 PNG）。可以指定落地到哪个页面。
- **5.3 归因**
  - 访客通过合作方链接进入时，用第一方 Cookie 只保存合作方编号，有效期 30 天。
  - 之后的订阅、咨询、订单都记录这个编号。
  - 隐私说明中补充这个 Cookie 的用途。
- **5.4 结算导出**
  - 按月、按合作方导出访客数、订阅数、咨询数和成交订单数，与 4.2 的汇总表和订单数据对应。
- **5.5 联合落地页模板**
  - 同一个模板可以加上合作方的名称和标志。**没有授权记录的合作方不能显示标志。**
  - 两个首批模板：
    - "First day in Shanghai"（酒店和公寓用）
    - "来访须知"（工厂发给来访买家）：入境、住宿、交通，并预留工厂可以填写的接待信息
  - 联合落地页使用 canonical 指向原页面，避免重复内容。
- ⏸ **停止点 D**：给我两个合作方试点的完整演示：生成二维码 → 扫码 → 订阅 → 结算表里出现这条记录。

## 阶段 7：内容运营支持（与阶段 3—6 并行，小步提交）

- **7.1 按类型复核**

- **7.2 发布前检查**
  - 政策类和指南类内容，没有来源链接或核实日期时不能发布。

- **7.3 结构化数据**
