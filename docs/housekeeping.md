# 家政与居家服务使用说明

第一批支持日常清洁、深度清洁、搬家与入住整理。城市沿用上海、北京、广州、深圳、重庆、杭州、武汉、南京；界面支持中文、英文、西班牙语、法语、德语、意大利语、阿拉伯语。城市可筛选不代表该城市已有可预约资源。

## 前台入口

- 服务介绍：`/zh/services/housekeeping`
- 服务商目录：`/zh/providers?category=housekeeping`
- 服务商申请：`/zh/apply?service=housekeeping`
- 客户咨询：`/zh/request?service=housekeeping`

首次咨询只填写区域、面积、房间数量、服务日期或可协商、频次、宠物与工具需求。家政单项需求不强制填写来华日期和同行人数。客户联系统一由华伴协调。

## 后台工作顺序

1. 在服务商后台查看申请原始资料；申请不会自动展示。
2. 经理或管理员填写家政内部核实资料：主体、人员、客服与上门人员语言、保险、售后、核实日期。未知事项须明确记录，不能替代凭证。
3. 管理员确认服务商状态及公开许可。
4. 内容中心创建“服务商介绍”，关联内部服务商，选择家政类别，补齐公开服务范围、计价、工具、入户与售后说明。客服语言和上门人员语言分别维护。
5. 按既有独立审核流程发布；管理员例外审核必须填写原因。公开项目指定的服务商必须覆盖项目全部家政子类。
6. 咨询进入需求后台，由所属团队／负责人跟进。在内部家政安排中记录范围、报价和客户确认，再填写详细地址和预约时间。
7. 实际转交必要资料时填写接收方、范围、客户授权依据、授权时间及转交时间。此记录仅追加，系统不自动发送资料。
8. 在内部安排记录人员、交接和售后；服务商暂停后不能再通过公开介绍发起咨询。

内容编辑权限不包含客户私人资料；沿用现有团队、负责人和内容板块权限。公开接口只输出发布的白名单字段，不输出详细地址、内部合作价或转交记录。

## Agent 与版本

`/api/public/catalog/docs` 说明家政筛选字段。Agent 可读公开范围、语言和服务边界。公开咨询链接携带发布版本；陈旧版本及不匹配子类由服务器拒绝。AI 可生成／翻译公开文字，不能据此修改核实事实、自动审核、派单或付款。

## 本地初始化与验证

`npm run seed:housekeeping` 仅在 APP_ENV=local 创建缺失的七语言介绍，不覆盖已有草稿、不创建真实服务商。

验证：`npm test`、`npm run typecheck`、`npm run build`、`npm run test:housekeeping`、`npm run test:catalog`。设置 AUTHZ_HTTP_URL 可附加真实网页／接口验证。

数据库备份：`backups/local-1793318514169.dump`。本地开发数据库已由开发模式同步结构；迁移文件 `20261030_000212_housekeeping` 已经独立空库迁移测试验证。不要对已自动同步的开发库重复执行该迁移；迁往 Replit／云端时使用标准迁移建库或明确的数据库迁移基线。该迁移不提供破坏性自动回退。

第一批不包括在线支付、自动派单、托育、老人照护和医疗护理。测试创建的虚构资料仅供本地验证，测试公开介绍执行结束后停用。
