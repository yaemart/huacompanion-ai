## 1.1 政策数据与权限契约

集合必须有可审查的结构化字段：国家 ISO 代码、展示名称、政策类型、最长停留天数、生效日、可空截止日、适用口岸/区域、官方来源链接、最后核实日期、核实人员工关系、备注和草稿/已发布状态。发布记录应保留对应修订号与发布时间。公开展示需要的限制说明与内部审核备注分开，内部备注及员工信息不进入公开投影。

建议采用一个政策录入主记录，并在既有审核发布事务中生成不可受后续草稿编辑影响的正式快照；“入境政策”集合是结构化录入入口，工作台操作复用原身份校验、提交/退回/审核规则。具体快照适配在1.1a固定契约，禁止建两套可各自编辑、互相不同步的数据源。普通公开查询只读正式快照。

默认不自动给现有员工新增政策板块权限。管理员分配范围后，编辑可保存/提交，审核员可在其范围审核；遵守原有不可自审规则及管理员例外原因审计。原运营客户数据权限不变。Payload REST、GraphQL、Local API、历史版本入口均须覆盖，不能仅靠隐藏后台菜单。

日期使用明确的日历日契约（政策生效/截止按来源规定，默认以中国当地日期表达），不可用浏览器时区或 UTC 午夜误移一天。截止日为空表示“来源未列截止日”，不宣传永久有效。保存草稿可容许资料待补，发布必须校验来源、核实日期、国籍、有效日期关系及停留时长；未来核实日期或不合法 URL 拒绝发布。

种子不带自动发布权限，不自动查询外站。示例为草稿，输出待核实清单；由工作人员逐条核实。此计划不提供或确认任何现实国家的现行免签结论。

## 1.2 查询函数的明确边界

建议输入为 `nationalityISO`、`arrivalDate`、已发布政策数组；输出包括判定状态、匹配政策、停留时长、条件、官方来源、最后核实日期及后台已发布的签证指引链接。函数不存储用户选择，不估算获准入境或离境日期。

相同国家可以同时存在多类政策，不随意只取第一条或把停留天数相加。优先展示适用日期内的一般免签方式，其他方式单列；240小时过境始终显示口岸、区域、第三国行程等待满足条件，不能仅凭国籍和日期给出“你可以免签”的无条件承诺，也不把240小时机械当作10个日历日计算离境期限。具体条件文案来自已审核政策记录。

| 测试场景                           | 必须得到的结果                                                      |
| ---------------------------------- | ------------------------------------------------------------------- |
| 截止前一天/当天/后一天             | 前两者在其他条件满足时适用；后者明确该日期尚未确认，不推测延期      |
| 生效前一天/当天                    | 前者不能提前适用，后者可以匹配                                      |
| 截止为空                           | 在生效日之后匹配，并说明以官方最新公布为准                          |
| 多条有效政策                       | 保留各自来源及条件，排序稳定，不累计天数                            |
| 一般免签+240小时过境               | 一般方式优先，过境为有条件备选                                      |
| 一条过期、一条仍有效               | 有效方式仍显示；不得把某一条到期误作全部政策失效                    |
| 全部已截止、未来尚未生效或未知国籍 | 待确认/没有已核实适用记录，加签证指引；不等同于法律结论“必须办签证” |
| 草稿、下架或修订未发布             | 不参与结果及无JS表格                                                |
| 闰日、非法日期、跨时区浏览器       | 合法日历日稳定匹配；非法输入明确报错                                |

## 1.3 公开页面验收

- 路径为 `/en/tools/china-visa-free-checker` 和 `/zh/tools/china-visa-free-checker`。SSR 输出完整已发布政策表；无记录时显示资料尚未准备及官方核实指引，不展示假数据。
- 国籍列表从已发布后台数据构建，并提供“未列出的国籍”状态；不为补全 UI 而硬编码现实政策。查询结果用同一纯函数生成，规则与无JS表格一致。
- 初始 HTML 可以包含全量公开政策，不能包含用户输入、员工资料或私有记录。选择国籍/日期不写 query string、Cookie、localStorage 或表单 POST；不接分析事件，阶段4再按获准方案另做。
- 每项结果都有来源及核实日期。免责提示说明这是已核实资料的辅助查询，是否准许登机/入境以主管机关及承运人核实为准。
- 输入有可访问标签、键盘顺序、错误提示、结果状态播报；小屏不横向溢出，表格可读。FAQ结构化数据与可见内容一致。
- 生产构建、移动配置运行 Lighthouse，记录 URL、构建提交、运行时间与报告。性能/可访问性均≥90；不以开发服务器得分或桌面分数替代。首次不达标时先修复再验收。

## 1.4–1.6 横幅、提醒与搜索验收

横幅引用后台正式政策 ID，不复制政策文案到代码。到期可按日期推导，“已延长”必须有经审核的新截止日和官方来源及前次正式版本对比；不能凭文章标题或系统猜测。待确认状态允许编辑在来源不明确时明确标记。嵌入普通内容页沿用审核发布流程。

提醒使用现有站内通知/待办及 worker，不新增 cron 服务。幂等键至少包含政策身份、正式修订、截止日期、30/7天阈值；恢复重跑和并发只生成一条。提醒生成前重新检查负责人有效及范围；无负责人时给有权管理员展示待分配事项，不能静默丢掉。 worker 停机后补跑应生成应有待办，已过阈值不重复发送历史通知。

搜索设置复用已有 SEO 全局及内容字段。GSC配置仅保存验证代码文本并作为验证 meta 值输出，不允许后台注入任意 HTML/脚本。功能关闭时工具从导航、sitemap、hreflang、llms中移除；开启时只列实际存在的中英页及互相对应的 hreflang。trial始终noindex；正式收录还需 B确认、上线冒烟通过及显式环境变量。
