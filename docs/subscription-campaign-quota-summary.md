# 群发任务：本地模拟余额与份额占位

本批验证“没有可用额度就暂停，以及并发操作也不能超额”。只做本地服务层，没有新增后台按钮，不发送邮件，也不接入 worker。占位收据表示历史模拟记录，不是发送许可。

## 可以测什么

- 管理员填写虚构剩余份数及原因；未设置、为零或过期时不能新增占位。
- 获授权主管只能操作本人当前已确认、已冻结的活动，只接受 `@example.invalid` 虚构邮箱。退订、取消、同意、邮箱或语言改变后不能新增占位。
- 多次、并发或大小写不同的同一操作编号不会重复占位；同一任务换编号也不能重复占位。
- 北京时间每日最多2,000份，同邮箱滚动24小时最多1份；重新设置余额不能绕过这两条。取消或过期不自动退回已占份额。
- 余额、占位及审计一起保存；审计提交失败不留下部分记录。通用后台和接口不能读取或修改私有账本。

## 怎么在本机验证

使用 Node24.22.1，保持本机演示 PostgreSQL 运行，执行：

```sh
npm run test:subscriptions
```

命令创建随机临时数据库、应用迁移并用虚构资料运行20组检查，退出后清理。最后应看到“PASS 本地模拟余额、唯一占位、并发限额、北京日界线、滚动24小时、权限与审计回滚”。失败时反馈命令、时间和错误，不附密码或环境文件。原3100演示、55442数据库和图片不重置。此批没有可点击的新页面，不宣称真人浏览器或手机验收通过。

## 限制与后续

模拟余额由服务器固定为1小时有效，用来演练过期暂停；本机演练需要重新设置余额。这不是对真实账户余额有效期的决定。真实余额核对、共用尝试次数和冷却、每秒传输限额、优先级、租约与实际投递仍未实现，原单封邮件限额不变。

一次独立复核无严重或重要问题，留下一项轻微性能待办：最坏逐个检查1,000个受限邮箱，会在共享事务锁内执行较多查询，可能拖慢其他本地业务操作；接入调度前应改为批量查询。

新迁移 `20261121_090000_subscription_campaign_mock_quota` 新增两张私有表，有记录时拒绝回退以防丢历史。本次只在随机测试库应用；原库升级前仍需数据库与图片配套备份并重启。无新环境变量、依赖或原种子修改，原始日志只在本机忽略目录。
