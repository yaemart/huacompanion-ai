# 群发任务：本地模拟余额与份额占位

本批验证“没有可用额度就暂停，以及并发操作也不能超额”。PR90合并后的补充批次将受限邮箱合并到一次统计查询：千人全部受限时不逐个查询，只有最后一名解除限额时也能找到这名候选。只做本地服务层，没有新增后台按钮，不发送邮件，也不接入 worker。占位收据表示历史模拟记录，不是发送许可。

## 可以测什么

- 管理员填写虚构剩余份数及原因；未设置、为零或过期时不能新增占位。
- 获授权主管只能操作本人当前已确认、已冻结的活动，只接受 `@example.invalid` 虚构邮箱。退订、取消、同意、邮箱或语言改变后不能新增占位。
- 多次、并发或大小写不同的同一操作编号不会重复占位；同一任务换编号也不能重复占位。
- 北京时间每日最多2,000份，同邮箱滚动24小时最多1份；重新设置余额不能绕过这两条。取消或过期不自动退回已占份额。
- 余额、占位及审计一起保存；审计提交失败不留下部分记录。通用后台和接口不能读取或修改私有账本。

## 怎么在本机验证

使用 Node24.22.1，保持本机演示 PostgreSQL 运行，执行：

```sh
npm run test:subscriptions
```

命令创建随机临时数据库、应用迁移并用虚构资料运行20组检查，退出后清理。最后应看到“PASS 本地模拟余额、唯一占位、并发限额、北京日界线、滚动24小时、千人限额批量查询、权限与审计回滚”。失败时反馈命令、时间和错误，不附密码或环境文件。原3100演示、55442数据库和图片不重置。此批没有可点击的新页面，不宣称真人浏览器或手机验收通过。

## 限制与后续

模拟余额由服务器固定为1小时有效，用来演练过期暂停；本机演练需要重新设置余额。这不是对真实账户余额有效期的决定。真实余额核对、共用尝试次数和冷却、每秒传输限额、优先级、租约与实际投递仍未实现，原单封邮件限额不变。

此前逐邮箱查询的轻微待办已补齐。回归先观察到1,000次逐邮箱计数，优化后两种千人场景都为0次，窗口摘要在原额度SQL中一次聚合，不使用跨事务缓存。353项单元测试及20组订阅集成通过，lint445警告持平；这不是正式吞吐量、锁等待耗时或真实投递验证。一次复核无严重/重要问题，轻微待办是测试若恰好跨过北京午夜可能偶发失败，需后续固定该场景时间基准。
