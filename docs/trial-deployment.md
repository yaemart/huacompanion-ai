# 试运行部署与验收

本文件随收敛阶段持续更新。当前只完成本地验证和部署材料；没有购买账户、建立付费资源、修改正式域名或开放真实客户收集。托管账户确定后，按本文继续实际环境验收。

## Node 与稳定开发环境

使用 `.nvmrc` 的 Node 24.22.1，运行 `nvm install`、`nvm use`、`npm ci`。`engines` 只接受 24.22.1 及以上的 Node 24；Node 运行时不再作为业务 dependencies 安装。

`npm run dev` 保留 Next Fast Refresh，但通过 `scripts/dev-env.mjs` 关闭 Payload HMR。实际回归曾捕获 Payload 热重载重建数据库映射时的 `Symbol(drizzle:Columns)` 错误；关闭后相同序列回归通过。修改 CMS 配置、集合、字段、权限配置后，停止并重新运行 `npm run dev`。生产 `next start` 没有这个热重载。

## 表单入口与前置网关

应用固定按 UTC 十分钟窗口计数：每客户端 60 次、全站 6000 次。先原子扣客户端额度，再扣全站额度；已经耗尽额度的客户端不继续消耗全站额度。窗口边界可能出现突发流量，网关仍需独立的客户端限速与连接数限制。

没有配置 `TRUSTED_PROXY` 时，应用忽略所有转发 IP 头，以 `PAYLOAD_SECRET` 签名的 HttpOnly / SameSite Cookie 识别浏览器。Next Request 不提供底层 socket 地址；此方案不能阻止清除或拒绝 Cookie 后重置身份。正式试运行应完成可信网关配置，不能将 Cookie 身份宣称为 IP 防刷。

启用代理身份必须同时满足：

1. `TRUSTED_PROXY=cloudflare` 只使用 `CF-Connecting-IP`；或 `TRUSTED_PROXY=nginx` 只使用 `X-Real-IP`。不使用 `X-Forwarded-For` 的第一个地址，不接受多个 IP。
2. 配置至少 32 个随机字符的 `TRUSTED_PROXY_SECRET`，网关必须删除外来 `X-Hua-Proxy-Secret` 并覆盖为该秘密值。应用恒定时间校验；缺失、错误、IP 无效或代理类型未知时返回 503，不退回 Cookie 身份。
3. 源站的客户提交入口必须只接受经过认证的网关请求；本实现要求有效秘密证明，直接提交缺失证明返回 503。平台可用时再叠加防火墙、私有网络或认证隧道，不能假定所有托管套餐提供网络 IP 白名单。仅填写代理名称不能证明来源可信。秘密值不能进入 `NEXT_PUBLIC_*`、前端代码、请求日志或 Git。
4. Cloudflare 部署前确认账户中的网关规则／Worker 或现有等效能力确实能够覆盖上述秘密头；本阶段不创建任何新服务接入，不假定某个付费能力已经购买。保留 Cloudflare 自己写入的权威客户端地址，限制源站访问。
5. nginx 直接面对客户端时，在受保护配置文件中设置 `proxy_set_header X-Real-IP $remote_addr;` 和 `proxy_set_header X-Hua-Proxy-Secret <secret>;`。若 nginx 前面还有代理，必须先限定可信上游再配置 real_ip，不能直接信任外来地址头。

网关还需：全站 HTTPS；`APP_URL` 使用同一个 HTTPS 域名；限制 `/api/intake` 请求体 32 KiB；按真实客户端设置合理速率（不高于应用每十分钟 60 次），同时限制突发／并发连接；丢弃畸形头；超时和健康检查；后台登录单独限流。不要把网站业务响应缓存用于后台、客户或 API。

两套表单均增加技术隐藏字段 `contactFax`。填写或传入非空／非字符串值会在存储、通知及配额消耗前被拒绝；正常的服务商 website 字段仍可填写。配额只保存客户端身份的密钥哈希，不保存原始 IP 或 Cookie；旧临时窗口定期删除。

网关实际环境必须逐项验证：有效网关提交成功、伪造秘密／地址不能替换网关值、直接访问源站失败、缺失或多值 IP 返回 503、一个客户端被限流不影响另一个。当前单元测试验证应用判断，不能代替网关、防火墙验收。

## 客服写入锁与容量边界

保留 `supportTransaction` 的 PostgreSQL transaction advisory lock `726280`。现有并发回归覆盖重复请求、接管／过期任务、人工与 AI 交接、跨会话额度和运营操作；它们不能证明将全部锁改成会话锁后，跨会话任务领取和共享额度仍无竞争。因此本阶段不更改锁粒度，也不改变报价或客户权限。

该锁在整个数据库内同一时刻只允许一个客服写入事务持锁，其他客服写入等待。读取和事务外模型调用不因此全部串行，但增加 worker 数量不会成倍增加此写入通道容量。写入吞吐理论上限约为 `1 / 平均持锁秒数`，还要扣除数据库和排队开销；例如 100ms 对应至多约 10 次事务/秒只是算术示例，**不是已测容量或 SLA**。试运行必须观察写入延迟、数据库等待和队列积压；持续积压时先限制入口并评估负载，不能直接扩 worker 当作解决办法。实际托管硬件负载测试待账户和环境确定。

后续若要按会话加锁，需要分别设计任务领取、每日共享额度和跨会话运营操作的锁，再补多 worker／多会话竞争与回滚测试后变更。

## AI 知识检索的已知局限

当前 `src/server/support/agent.ts` 对查询做字符词组提取，再在同语言已发布内容 JSON 中按是否包含关键词计数排序，取前六条，每条文本截取 2400 字符。不是语义检索，不识别同义表达与跨语言含义；中文分词较粗、重复词可能影响分数、无匹配仍可能返回零分内容，长正文截断可能丢失上下文。它不保证回答正确，也不能替代员工确认。

本阶段保持原实现，不添加向量库、嵌入模型或新 AI 能力。模型账户、额度、知识质量和真实效果尚未验收，AI 文字客服保持关闭；后续再独立评估改进。

## 保留的业务验收与回退规则

使用虚构资料完成咨询→服务单→报价草稿→发出→人工核实成交／资源确认→履约→完成。客户中心本阶段关闭；历史已实现的客户验证码与报价确认流程仍须保留原权限，只有后续单独授权启用时再验收真实邮箱、登录退出、关联撤销和草稿报价隔离。

以普通运营、主管、内容编辑分别验证数据范围；负责人更换或授权撤销后立即失去原数据访问。对外不得出现内部成本和交接备注。报价被新版替代、撤回或过期后不得确认；暂停后重新沟通落实安排。内容草稿、审核、发布、下架仍保持分离；编辑公开内容后必须重新发布。

部署使用独立试运行库与独立 `PAYLOAD_SECRET`，不直接复制本机测试库和账户。`APP_ENV=trial`、`APP_URL=https://实际域名`、`NEXT_PUBLIC_FORM_MODE=trial`；最后一项在构建时生效，变更后重建。先备份再执行迁移，不把环境改成 local 绕过迁移；`push` 只允许本地。

保留旧镜像及匹配的数据库和图片备份。迁移失败时停止网站和两个任务进程的写入，恢复配套备份到隔离目标，核对后再切换连接；不得直接向下删业务表或用旧代码掩盖 schema 不兼容。日志不记录密码、验证码、会话令牌或完整客服消息。

`INTAKE_ENABLED=false` 保持到 HTTPS、隐私主体及联系渠道、`PRIVACY_VERSION`、网关、权限、备份恢复和端到端验收均落实；再由负责人明确开放试运行。站内通知先使用，邮件需 Resend 已验证发件域名、环境三项和后台 emailEnabled 共同开启。当前入口只允许 local／受控 trial；转正式发布另行审批和验收。
