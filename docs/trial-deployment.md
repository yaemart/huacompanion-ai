# 试运行部署与验收

## 本地验收

先使用虚构客户资料，在业务工作台完成咨询→服务单→报价草稿→发出→客户确认→资源确认→履约→完成。客户登录需要配置邮件并启用后台客户设置；自动测试使用注入适配器验证，不能把测试成功视为真实邮件开通。

检查普通运营、主管、内容编辑各自可见范围；更换咨询负责人或撤销客户关联后，原访问者不能继续取得资料。客户不得看到草稿报价、内部成本或内部交接。报价被新版替代、撤回或过期后不能确认。暂停后须重新沟通落实安排。

内容工作台编辑、审核、发布与质量复核分开；对公开内容的修改必须重新发布。过期复核状态提示需要工作人员处理，不等同于自动重新核实事实。

## Replit 试运行准备

以下为本项目部署要求，不表示已在 Replit 验证可用。先确认所选运行环境支持常驻 Web 进程、独立后台任务和持久化存储；不能保证进程常驻的方案不可承担通知和客服任务。

1. 使用独立试运行数据库，不直接复制带测试账户的本地库。密钥通过部署环境的秘密管理配置，采用独立 `PAYLOAD_SECRET`。
2. 设置 `APP_ENV=trial`、`APP_URL=https://实际域名`、`NEXT_PUBLIC_FORM_MODE=trial`。后者在构建时读取，变更后重新构建。
3. 数据库自动推送仅在 local 开启。备份后执行 `npm run payload -- migrate`，再构建与启动；不要通过切换为 local 绕过迁移。
4. 构建 `npm ci`、`npm run build`，Web 进程 `npm run start:host`；按平台要求设置端口。分别监管 `npm run support:worker` 和 `npm run workflow:worker`，记录退出与失败告警。
5. 当前图片读写固定在 `.local/content-media`。部署必须提供持久卷并备份；若托管环境无持久卷，先改造对象存储并完成上传、私有访问和恢复测试，此项未完成不得上线图片功能。语音等数据库内容随数据库备份，并依客服保留策略处理。
6. 配置 HTTPS、日志保留、数据库定时与异地备份，演练数据库和图片配套恢复。不要记录验证码、会话令牌或完整客服消息。
7. 以真实业务主体核定隐私说明和联系渠道，设置 `PRIVACY_VERSION`。保持 `INTAKE_ENABLED=false` 直到端到端验收完毕，随后明确设为 true 才开放试运行咨询。

## 按需开启

- 站内通知先使用；邮件需验证发件域名并设置 `WORKFLOW_MAIL_ENABLED=true`、`WORKFLOW_MAIL_API_KEY`、`WORKFLOW_MAIL_FROM`，通知邮件另需后台 `emailEnabled` 开关。
- 客户中心需后台 `customer-settings.enabled`。使用受控真实邮箱测试一次性验证码、退出、跨设备查看和撤销关联；没有有效身份关联时不得自动显示历史咨询。
- AI、转写、语音播放和实时通话按各自文档配置兼容接口、额度与开关，先小范围测试再启用。未配置时应显示不可用并支持人工处理；不要伪造 AI 响应。
- 不包含在线支付、App 商店发布、真实 Replit/AWS 部署。这些需要后续独立接入和验收。业务 AI 草稿与人工审核流程已实现，真实模型接入见 `business-ai.md`，不会自动报价或发给客户。

## 发布与回退

先备份，再迁移，再构建，最后进行首页、七语言客户中心、员工登录、咨询提交、内容发布、报价确认及工作进程冒烟测试。保留旧应用版本和匹配备份。新增迁移不支持直接向下删表；失败时停止写入并恢复匹配的数据库与媒体备份，核对后再恢复服务。不得用回退代码掩盖数据库版本不兼容。

开放真实客户前必须落实：部署账户和运行规格、HTTPS 域名、持久化 PostgreSQL、图片存储、备份恢复、邮件发件身份、值班人员及已核实内容。当前代码层面准备不能替代这些实际条件。
