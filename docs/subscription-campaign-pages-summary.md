# 政策群发草稿：本地亲测指南

本批接入中文后台页面和管理员授权区。获授权主管只看自己的活动和汇总人数，不取得邮箱名单；管理员自己做活动也要先明确授权。仅保存草稿，没有测试发送或正式发送按钮。

## 启动和账号

使用 `.nvmrc` 的 Node 24.22.1，保持原演示 PostgreSQL 运行，在项目目录执行：

```sh
npm run test:subscriptions -- --preview
```

这会启动 **3186 独立临时预览**；不修改原 3100 演示或重置已有数据。终端显示本次 `preview-accounts.json` 的完整位置，文件只保存在本机，包含管理员、两位主管和运营的随机测试密码。用文件中的账号登录 `http://127.0.0.1:3186/admin`。结束按 Ctrl+C，临时数据库、账号文件和预览副本自动清理；再次启动即回到初始状态。

## 建议按顺序测

1. **管理员**：从仪表板打开“政策群发草稿与主题授权”，确认本人还不能做活动；选“预览主管1”，授予政策更新操作权。返回后台点“登出”，等回到登录页后再换账号。
2. **主管1**：打开同一入口。直接保存时，空选择应提示“请选择 1 至 10 项已发布政策”；勾选一条醒目标注的虚构政策后保存，应看到“第 1 版”、中英文预览、来源、核实日期及预估人数。全程没有邮箱名单和发件操作。
3. **主管1**：从“我的活动草稿”重新打开，已选资料仍勾选；再勾选另一条，保存成为“第 2 版”。原版本保留在系统中。人数为当前估计，缺语言资料时排除对应语言，不替换语言。
4. **权限**：管理员给主管2授权后，主管2的活动列表仍为空，打开主管1的草稿链接应被拒绝。管理员撤销主管1权限后，主管1再次打开旧链接也被拒绝。运营账号直接打开 `/subscription-campaigns` 应显示无权操作。
5. **手机布局**：缩窄窗口检查勾选、保存及长来源地址换行。本轮已测 390 像素无横向溢出，保存按钮高 50 像素。真实手机和新人无提示测试仍由你验收；问题记截图、账号角色、操作步骤、预期和实际结果。
