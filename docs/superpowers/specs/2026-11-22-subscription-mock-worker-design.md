# 本地模拟营销独立 worker

PR105合并后基线 `02bec32f150c88c1496424e9015cb2a8a396718c`。用户明确要求独立进程自动领取、开始并记录模拟结果，
原权限/额度/邮箱共用预算/全站1秒/确认资料优先/重试保持，不清除review、不接真实传输。

## 范围与方案

本批为现有服务的单条接线，不新增发送引擎。执行者推荐并已告知：专用命令显式指定主管、活动当前版本、
固定模拟结果（默认accepted；可选temporary/rate-limited/unknown/permanent），只消费已占位任务。
也可扫描所有主管活动，但会扩大后台处理范围；也可并入workflow worker，但其任务含真实适配器且没有主管活动作用域，
不适合本批仅本地演练。采用专用命令，不自动随Web/演示启动，不自动准备余额、占位、确认或优先邮件消费。
B默认规则与先本地模拟已经用户确认；本轮直接任务授权继续这条接线。具体CLI方式及默认模拟完成为执行者实施选择。

## 行为

命令：`npm run subscriptions:mock-worker -- --staff ID --campaign UUID --revision N [--outcome accepted] [--retry-after-ms N] [--once]`。
APP_ENV必须local，所有参数先严格校验再初始化Payload；无新依赖/产品环境变量。
每轮重新读取员工，仍由原候选、claim、begin、result逐步核对当前角色/独立主题授权/本人版本/确认/资格/暂停取消。

无内存凭证时读下一候选并claim，有未开始凭证时尝试begin；短时dispatch等待保留同一凭证，不续期。
原邮箱冷却释放内存凭证，原未开始租约仍存在；使用数据库新鲜时钟丢弃过期的未开始凭证，再走原候选恢复。
只有begin确认attempting才记录启动时固定的模拟结果，终态/等待不得伪装成功。按原结果服务存储，绝不调用邮件适配器。
一轮只处理一项；循环每秒检查一次，--once只运行一轮。空闲/冷却/优先等待是正常回执，原服务决定是否有进展。
SIGINT/TERM停止下一轮，当前轮完成后关闭Payload；SIGKILL或异常不补结果。
服务异常令本次worker停止，日志只含安全状态和编号；不把异常当temporary/accepted，不自动重放不同命令。
重启后已开始任务由原规则停review，不接管、不清除；未开始过期租约按原规则可恢复。
