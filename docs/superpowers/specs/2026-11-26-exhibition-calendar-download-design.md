# 单展会日历下载设计

状态：用户接受“整届一个全天日程，分期放说明”的建议，并要求继续下一步；沿用原生执行、测试、交接、推送草稿PR，不自动合并。该短设计记录已接受范围及实施者边界选择，不重复申请已给出的实施授权。

## 目标与方式

PR120已合并，起点main `3789cf9c3978a61259e7d71c5439b43ed340de79`。本批完成阶段3.3单展会`.ics`下载，让读者把展期加入自己的日历。
采用现有Next Route Handler在服务器生成文件，复用`listPublished`的公开快照与语言隔离；详情页使用普通链接，无浏览器脚本或新依赖。相比浏览器拼装，服务端可直接保证下载时的当前公开版本；订阅式日历会引入持续更新语义，留后续另议。
用户选择整届一个日程，分期作为说明；不引入分期身份或按期导出。一次性导入后不会自动更新，页面和文件说明需提示改期重新下载、出行前核对官方信息。

## 日期、身份与字段

- 使用总体起止日期的全天事件，包含结束当天，不虚构开馆/闭馆时间，也不以UTC午夜冒充当地时间。
- 按[RFC5545](https://www.rfc-editor.org/rfc/rfc5545.html)使用DATE起止值，结束值为总体结束日期次日；CRLF分行，按UTF-8最多75字节折行且不拆字符，TEXT转义反斜线、分隔符和换行。
- 仅导出已公布且总体日期严格有效的公开展会；已结束可作为历史日程。待公布、延期、取消、日期缺失/逆序/无效暂不可导出；末日无法用四位年份表示次日时拒绝，不生成截断日期。
- UID使用固定项目命名空间、contentKey及语言的SHA256稳定摘要；修改标题、slug、日期、内容版本不改变UID，不随请求Host或部署域名改变。不同语言各自独立，不承诺跨语言合并或客户端重复导入时自动覆盖。
- 文件包含名称、场馆及中英地址、概要、分期名称/日期/题材、详情网址、官方来源/核实日期和一次性导入提示。分期未知日期仍显示待确认，不推导总体日期。
- DTSTAMP为导出时间；有效发布元数据提供LAST-MODIFIED和SEQUENCE。无收件人、组织者邀请、重复规则或VALARM；用户日历软件自身的默认提醒不由本站控制。

## 接口、展示与权限

新增只读`GET /api/public/exhibitions/calendar?locale=<语言>&key=<contentKey>`，详情页提供本语言下载链接与一次性导入提示；不满足导出条件时显示本语言说明。
有效已启用语言和内容标识在数据库初始化前校验，错误400；该语言没有当前公开展会（草稿、其他内容类型或已撤下）404；公开但日期/状态不可导出409；内部异常503，不泄漏错误或凭据。语言配置本身损坏亦返回503且不初始化数据库。
成功响应`text/calendar; charset=utf-8`、ASCII安全附件名、`Cache-Control: no-store`及`nosniff`。URL从已配置APP_URL的HTTP(S)origin产生，不使用请求Host；配置不合法返回503，不输出错误地址。
公开读接口只读，不改草稿、快照、版本、审计或订阅；原审核、来源核验、语言、试用访问/维护门禁及公开POST拒绝保持。旧快照无分期仍可下载，未审核草稿不能进入文件。
末尾复核修正：现有公开展示会把带过去日期的待公布展会显示成已结束，保留此既有行为；服务在转换前计算只读`calendarExportable`元数据，下载与详情同时遵守，不将未确认日期作为历史日程。该可选公开字段不持久化，保存时的白名单移除客户端传值，服务从原发布快照重算。原`expiresAt`不自动下架的语义不变。
