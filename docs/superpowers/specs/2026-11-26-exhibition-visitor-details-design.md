1. **自由文本分期说明**：新增一个分期大文本和四个到访文本，实施最小，但各期日期与题材只能靠人辨认，后续导出难以复用。

## 数据和兼容

在`Exhibition`中增加以下可选字段，已有发布快照和草稿均允许不含这些字段：

- `phases?: { name: string; startDate: string; endDate: string; theme: string }[]`。
- `transport?: string`：到达场馆的交通说明。
- `buyerRegistration?: string`：外国买家的登记流程、凭证及待确认要求；复用现有官方登记网址，不新增登记接入。
- `stayAreas?: string`：适合住宿的区域和选择依据，不创建酒店推荐、预订或可用性保证。
- `firstVisitTips?: string`：首次参展的准备提示。

实现者提出的限值：最多12期，名称最多200字符、各期题材最多2000字符，四个到访字段各最多5000字符。数据结构只接受列出的字段；公用投影明确白名单复制，不传播原对象或额外内部属性。既有总请求体大小限制保持不变，单字段限值不意味着所有字段都填到上限仍可提交。

新建表单使用空字符串和空数组；读旧资料时在表单/公开投影中做缺省处理，不后台批量改写旧记录。不改变已有必填字段和旧发布条件，不因新增可选字段阻止旧内容重新发布。
可选文本未填或只有空白时，详情页不显示该项；`phases`未填或为空时不显示分期区域。草稿保存、版本、预览、审核发布均通过现有内容流程。

## 分期语义

- 分期仅为该展会的说明，不创建新的展会身份、独立公开路由、咨询对象、筛选候选、JSON-LD事件或提醒任务。
- 现有“某届某一期”已单独建展会的内容继续有效，无需自动合并或转换。
- 展会总体起止日期仍控制列表筛选、排序、结束状态、咨询资格和既有Event JSON-LD；本批不改成由分期日期推导。
- 分期保留录入顺序；可以添加/删除，默认不排序；不同分期可以日期重叠，适应平行主题，不要求连续。
- 草稿中分期名称和题材允许暂空；发布时，已新增的每一期名称与题材必须有非空内容，未填完整的空行须补齐或删除。
- 每期日期允许同时为空（详情显示本语言“待确认”）；填写日期时必须两项完整、严格有效且开始不晚于结束。
- 当总体日期已知时，已填的分期日期须位于总体区间内；总体日期未知且原状态允许未知时，可以保存已知分期，仍不推导总体日期。更改总体日期导致已填分期越界时提示人工核对，不静默移动或删除分期。
- 不为分期提供 .ics 或独立订阅。后续如需要按期导出/提醒，另行确定稳定身份与改版规则。

## 编辑与展示

在现有`ExhibitionFields`增设“展会分期”编辑区及四个到访文本，沿用`ContentTextField`的示例/模板行为。示例全部明确虚构，不自动填入或发布事实。分期添加/删除与文本修改都走父表单现有dirty、修订和保存规则。
公众详情页在基础信息之后展示分期，再展示已填写的到访资料；保留纯文本换行和长文本换行，避免窄屏横向溢出。沿用现有样式，不重排列表页。
七种语言提供对应标签；内容仍由该语言自身的版本维护，不跨语言抓取或回退到其他语言。中文地址与英文地址沿用当前专用字段。
复用现有官方来源/最后核实日期和人工审核确认，并把新增分期/到访资料纳入审核提示。资料可留空，不编造交通线路、登记条件、住宿事实或主办方/华伴承诺。
本批不填充真实展会资料，不调用AI、地图、酒店或报名服务，不自动抓取官网。
