# H 本地回执收尾设计

用户已确认：处理三个轻微项、补只读回执汇总，退订邮件组装作为真实试发前门禁；本批测试、交接、推送、草稿 PR，不自动合并。沿用原生实施及现有技术栈。

## 范围与选择

在既有活动工作台增加一个独立只读汇总，复用活动本人、现职主管、政策主题授权与最新草稿版本守卫。独立刷新走既有同源 JSON API，不导航、不保存、不重新测试或重置模拟确认。另建全站运营台会扩大权限和名单暴露范围，仅修改任务状态则混淆模拟接受与投递回执；本批采用独立活动汇总。

实现者决定：只提供汇总，不提供逐人明细或邮箱；这满足本批“只读回执汇总”，不代表完整运营分析后台已交付。沿用既有组件样式，无新依赖、集合、迁移或环境开关。

## 汇总口径

- 统计原冻结名单（含后续版本的历史），显示冻结版号、是否当前版、原名单邮箱数和统计时间。
- delivered、hard-bounce、complaint、provider-suppressed 各自按本活动邮件级回执中的邮箱摘要去重；多种结果可以重叠，不能相加当总人数，不把最后到达事件覆盖历史事实。
- “当前营销拒发”按原名单邮箱摘要匹配全局拒发表，包含来自其他活动及无 source_id 邮箱级抑制。邮箱级事件不伪装本活动某封邮件回执。
- 无回执不是未送达；模拟完成不是送达；送达不代表阅读。取消、暂停、来源过期和改版不隐藏合法历史。
- 没有冻结名单时显示空状态。刷新失败保留旧数据，明确标出旧统计时间。刷新不改变本页未保存选择、写锁、控制结果未知或续发状态。

## 三项修正

1. 严格检查签名回执原时间的年月日及时间组成，允许合法闰日、分数秒和时区偏移，拒绝不存在日期、24 点及越界偏移；保留原时间来源指纹和 UTC 归一化。
2. 删除把测试 HTTP 适配器的 GET405 当框架证据的断言，使用安装版本的 Next 方法分发表与实际路由导出证明 GET/HEAD 不进入 POST、无数据库初始化。
3. 独立 PG 事务测试非空迁移回退保护：只有绑定而无反馈、签名反馈、邮箱级反馈、供应商拒发。失败后显式回滚事务并比较所有表指纹，保留原空表回退往返测试。

## 安全与验收

保持内容→业务写锁顺序，汇总使用仅元数据守卫，不读取订阅名单、不写反馈、审计或确认状态；API 保持认证、同源、JSON、私有 no-store。测试本人/他人、撤权、停职、旧版、错误输入、非 local，重复事件去重、跨活动隔离、全局拒发及读取前后全表指纹。

完整 npm run check、串行 npm run test:subscriptions，以及实际组件桌面/窄屏验证；更新一页中文说明、handoff 和 progress。既有演示库不自动迁移或 reset，测试仅独立虚构随机库。

真实发送、公网接入、清除拒发、强制重试、费用、部署均不开放。真实试发前另须完成当前同意版本退订凭证、邮件退订正文与 List-Unsubscribe 组装及验收；本批完成后仍只称 H 本地模拟范围收尾。草稿 PR 合并由用户决定，展会日历从合并后的最新 main 开始。
