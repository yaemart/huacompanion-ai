## 管理员入口与启动顺序

提议命令如下；--once只跑一轮实际本地模拟流程，**会生成待发**，不是只读预检：

```sh
npm run --silent exhibition:reminders -- schedule \
  --auth-file .local/private/admin.jwt \
  --manifest-file .local/private/targets.json \
  --state-dir .local/reminder-runs/run-NEW [--once]
```

只支持上述参数；不接受token/staffId、日期、间隔、后台化、force/retry/send/clear或恢复旧目录参数。help不初始化数据库。输入与非local/清库开关错误须在动态加载配置前拒绝；JWT和清单一次读入，之后改文件不换身份或扩大范围。

清单精确形状为{version:1,targets:[{key,locale}]}，合法本届标识、zh/en、1–20条、无重复或额外字段；规范字典序固定在内存。文件须当前uid、0600、常规单链接、有界，禁止符号链接/特殊文件。启动展示范围与“本地待发，未发送邮件”；不跟随下一届或发现新目标。

顺序：检查参数/输入/候选目录→原安全Payload初始化（禁schema/建库/types/遥测与普通日志）→原生现职管理员→withExhibitionScheduler取得try单实例锁→只读核对DB状态→创建新独占目录并保存头资料→检查停止请求/身份→session.begin→持久保存已开始资料→进入循环。

目录创建前可检查路径，但最终创建时必须再次核实，并依赖排他mkdir而非“先检查不存在”。DB有pending时直接拒绝，不创建新运行或代为恢复。读到坏状态/未知版本拒绝，不回退。旧running但无pending允许新明确启动，由原begin规则替换；不把running标签当在线证明。

## 独占目录与持久文件协议

既有父目录由管理员准备；新叶目录用非递归排他创建、0700、当前uid。父路径使用规范绝对路径，各组件不接受符号链接；写入位置不得由其他用户写入。当前验收面向macOS/Linux的uid、NOFOLLOW和目录同步语义；不声称Windows或不支持这些保证的文件系统可用，能力不足直接拒绝生成。

只持有本次新建目录及文件，保存目录device/inode/uid身份；文件操作前后核实目录未替换，文件用NOFOLLOW/O_EXCL和0600，不跟随链接或覆盖已有目标。原子发布需同步文件、成功关闭、独占发布并同步包含目录；新目录在父目录中的条目同样同步。任一步失败不把文件称为已持久化，不继续应用。协议不承诺防御同uid恶意进程或恢复不可靠的网络/同步文件系统；父目录必须可信且本地。

文件只追加，不更新旧文件。建议精确版本1、每份元数据最多16KiB、回执沿原2048字节上限：

- run.json：本地运行UUID、固定规范清单及摘要、数据库端点绑定摘要、创建阶段。无JWT、密码、明文URL、邮箱/订阅ID；摘要是绑定标记，不是授权。
- started.json：DB runId、owner、begin revision、对应本地运行UUID。以上为私有恢复元数据，不打印终端；runId不作为凭证。
- operations/<单调序号>/：本次范围与原封套receipt，以及不可覆盖的planned/prepared/applying/finished阶段文件。目录0700、文件0600、精确字段/类型/范围/版本校验；未知格式拒绝，不修复或删证据。
- stopped.json：仅在已知正常停止且可持久化时追加。没有它不证明数据库未提交或进程仍在线。

operations目录及阶段文件也要按包含目录逐层同步。无变化轮次不建操作目录、不写文件/心跳审计。历史目录原样留存，手动归档/删除不在本批入口内。

数据库绑定取实际连接的规范非秘密端点/数据库身份信息形成摘要，清单用固定编码摘要；不能把连接密码或JWT混入。它用于避免把本地证据误用到别库，不声称识别所有物理数据库克隆。**DB可信的run/owner/pending digest/scope和生成审计始终是恢复权威**；即使端点摘要相同，也不能凭文件解除或重放。端点/凭证变化或证据缺失，只读查询/明确恢复仍走既有入口，不自动迁移绑定。

## 串行单轮与异常顺序

每个清单目标依次执行，上一目标完整结束才进入下一个：

1. 检查停止请求、原生当前身份；调用原只读preview，取得同一快照的当前已审核资料/日期/资格/拟新增取消。配置门禁阻止则整次停止，不改开关。
2. 无新增且无取消只输出必要汇总，不apply或追加心跳。有变化则新建操作目录，完整持久化原receipt及planned元数据。
3. 再检查停止/身份，session.prepare持久追加pending；确认落库后保存prepared阶段。任何失败/结果未知停止，不进入apply。
4. 再检查停止/身份，持久保存applying阶段，再次检查停止后才session.apply；必须使用同一活会话的私有许可及原三锁内DB身份复核。不能走普通手工入口替代。
5. 明确apply成功后，按原授权完成session.finish并确认落库，再持久保存finished。任一步失败/未知即停止，不自动重试、重新预检、换封套、跳目标或隐式resolve。

每个目标独立提交，后续目标失败不回滚前面的已提交结果。清单内当前已审核修订/日期/退订/拒发等变化仍由原预检与生成服务核实取消旧held，终态不复活；非30/7日只有原服务允许的失效取消。held不是当前可发或真实已发送。

循环由单个await链驱动，不用setInterval或重入回调。第一轮立即，正常完成后用单调等待计时60秒；每段最长5秒发起一次身份复查，SIGINT/SIGTERM可立即唤醒等待。纯等待器可测试替换，产品不提供自选时钟/日期/间隔。休眠恢复后不补tick，只核对当前身份和数据库当前业务日；会话失效停止。

## 停止、提交边界与重启

SIGINT/SIGTERM只设置停止闩并唤醒等待，不在信号回调发DB写入、不启动新目标或新轮次。重复信号不启动第二套清理；不以第二次信号强制重试、清除历史或声称回滚。SIGKILL/掉电无法正常收尾，按未知结果核实。

尚未prepare时，停止后不prepare/apply；若仍有有效授权、已知当前run且无pending，可session.stop正常登记idle。未决已经持久化但apply未启动时，保留pending，关闭会话，由新恢复会话显式核实结束；同一session不能自恢复。

已经进入apply事务时等待它完成或按原超时失败。原最后一次锁后鉴权批准的提交可完成，信号不是追溯撤销。若apply明确成功且身份仍有效，允许完成这一操作的正常finish，不再处理新目标；身份失效或结果未知则不补写finish/stop。每条SQL有界不等于整个事务/清理总时长固定10秒，不强杀其他后端。

finish提交成功但响应丢失、或finished文件失败时，本进程必须停止并留证。DB若仍有pending，全库后续调度继续阻断；若finish已实际提交，DB可能已无pending，不能假称全库仍阻断。这时先用status/inspect核实，不拿resolve当可重试按钮，不自动续跑；后续新的显式启动仍按原begin及当前资格规则判断。查询本身不清pending。

begin提交/started保存失败时不apply；仅在明确run、无pending且当前授权有效时可正常stop，否则只关闭自己资源并提示核实。目录留下多少阶段都不证明“绝对未执行”。启动永远不读取旧目录继续应用；旧证据通过原inspect/status/resolve链路由管理员核实，不加自动恢复入口。

正常--once完成/无变化退出0；SIGINT/SIGTERM正常停止分别130/143；拒绝、身份失效或未知结果退出1。退出0不是送达证明；未知结果提示优先于普通停止提示。全流程finally释放本会话连接、Payload和自己的等待/信号处理器，不停止网站/worker，不解除别人的锁。
