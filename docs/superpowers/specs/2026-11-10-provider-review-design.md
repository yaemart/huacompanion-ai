# 服务商主管审核（E P1第二批）

用户已批准主管在原数据范围内核实通过、签约、暂停；每次原因必填并审计。
PR42已实核合并main d995b2826241291285d32c2f2207e17f9dafb59b，本批从该main新开分支。
只实施此授权，不把主管变成管理员，不自动公开、不改咨询／报价规则。

## 实现选择

采用专用审核命令接口＋现有Payload版本／审计。与直接开放状态字段相比，权限扩展只在
受控动作里生效；原字段普通CRUD不能更新，服务端hook还拒绝绕开命令的真实状态变更。
不加schema、迁移、种子或依赖。原applied／needs-info可读取；三个按钮对应verified／contracted／paused，
不凭空增加签约前置状态或服务商自审限制。

事务先锁目录726271再锁业务726281，与原providers hook顺序一致；锁内重读当前员工及申请范围，
主管同团队、管理员全范围、普通运营／审核人／停用或已撤权员工拒绝。
每次携带原updatedAt、随机重试键、原因，校验现有记录再改；过期拒绝，重试只返回原结果，
同键不同内容拒绝。原审核结果之后又有修改时，旧重试也提示重新读取，不伪装成最新资料。
状态、审计、版本及既有下架钩子同事务，审计失败整体回滚。

核实／签约保留原公开许可，不从false变true；暂停将许可false，以满足既有暂停校验并防止
随后重新核实时自动上架。恢复核实后，仍由管理员另行许可展示。暂停沿用原服务项目停止接单逻辑，
不恢复已停项目；不创建合同、不发送消息或收钱。

界面保留当前只读状态，增加原因及三个明确按钮。普通运营看到无审核权限提示。
有未保存资料时先保存；请求失败保留原因。成功只更新相关字段和Payload保存基准，
不刷新整页、不丢独立跟进输入；真实其他人改动仍须冲突提示。
主管不开放全站审计读取，只写入审计，管理员原审计入口可查看记录。

浏览器实际发现原Payload只在首次编辑时异步检查过期，快速保存可覆盖他人修改。
补虚拟editBase字段（afterRead派生updatedAt，不落库）：REST更新必须携带上次读取的标记，
在原锁内比较最新版本，缺少／过期均409；LocalAPI传入标记也比较，受控审核仍用自身原子版本校验。
正常后台自动携带，审核成功同步标记和保存基准。旧编辑页需先刷新；其他REST调用方先GET再携带editBase。
