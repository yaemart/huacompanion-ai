## 方式比较与推荐承接

1. **显式启动的原生前台进程：采用。** 使用当前管理员JWT和固定清单，在有效会话内周期检查，终端可停止；符合用户已选的本地受控方式，复用现有服务。代价是进程关闭、电脑休眠或会话失效时不提供持续运行保障。

实现采用项目现有Node/TypeScript方式，不引入调度平台或依赖，不加入`local:start`默认启动链路，不新增公开API、运营页面、系统任务或真实发件worker。

## 启动、身份与清单

拟提供独立命令，例如`npm run --silent exhibition:reminders:schedule -- --auth-file PATH --manifest-file PATH --state-dir PATH`；辅助`--once`执行一轮真实流程后退出。具体名称由实施计划确认，不接受密码、裸staffId、命令行JWT、自选日期、发送、清除历史或强制重试参数。

实际操作仅`APP_ENV=local`。初始化前拒绝`PAYLOAD_DROP_DATABASE=true`、非法参数、无效私有文件和清单；关闭schema push、自动建库、类型生成、遥测与普通Payload日志，正常退出/失败销毁本进程资源。`--help`惰性，不读取凭证或连接数据库。

认证文件沿PR125：当前uid、0600、常规单链接、有界原始JWT；结构检查不替代原生签名、会话、现职管理员判断。启动只读取一次JWT，不自动登录、刷新、延长有效期或热替换身份。现有员工会话时长为7200秒，实际剩余时长取决于原登录时间。

清单使用私有、有界文件，例如：

```json
{
  "version": 1,
  "targets": [
    { "key": "fair-content-key", "locale": "zh" },
    { "key": "fair-content-key", "locale": "en" }
  ]
}
```

**实施者建议默认值：** 文件上限16KiB，1至20个不重复范围；只接受上述字段、合法contentKey及zh/en。文件及状态目录禁止符号链接/特殊文件；输入文件仍为当前uid、0600、单链接，状态目录为当前uid的0700私有目录。标识不是名称、slug或下一届关联。重复范围拒绝，不静默截断或去重。

启动将清单规范排序并固定在内存，展示本届标识/语言、周期和“本地待发，未发送邮件”；修改清单或认证文件不会改变运行中的授权。运行范围不会从公开资料发现新目标，不追随nextEditionKey，不扩为全部展会。调整清单需停止、重新核实未决操作并明确重启。

清单授权的是所选本届/语言的持续资格核实，不固定某份草稿或旧公开修订：每轮仍只能读取当前已审核公开快照。公开修订、日期或订阅状态改变后，下一轮须重新预检并按原服务处理，不能沿用旧名单/旧日期。原人审、来源核验、自审例外、发布与员工权限均不改变。

## 周期、业务日期与停止

**实施者建议默认值：** 成功启动后立即一轮；一轮完成后等待60秒再开始下一轮，同一进程始终串行处理，不重叠、不并行生成、不积压补执行错过的轮次。`--once`使用完全相同的单轮路径，方便本地验收。

空闲等待以最长5秒的小段唤醒，检查停止信号及当前原生管理员会话；会话过期、登出、停用、角色变化或原管理员权限失效时终止。每个目标预检/应用仍进行原生认证及事务内锁后复核。定时器只控制等待间隔，不决定提醒业务日期。

生成仍以数据库当前时钟转换的北京时间自然日为准：仅距总体开始日恰好30/7天生成，漏过该自然日不补旧档，不按分期生成，不信机器时区或客户端日期。当天晚些时候新确认的合资格订阅可在下一轮进入，不能用“今天已跑过”跳过后续资格复核。

电脑休眠/进程暂停后，只检查当前会话和当前数据库日期，不补跑暂停期间的每个tick。若仍有效，可检查当天当前窗口；若已过期则停止。跨午夜的封套由原服务拒绝；不通过客户端改日期绕过。

SIGINT/SIGTERM停止发起新目标和新轮次，空闲时及时退出。已进入的事务保留原契约：最后一次锁后鉴权决策有效后可完成提交；其后登出不追溯撤销已批准的提交，角色变更仍由原锁保护。建议本进程每条SQL及锁等待超时10秒，超时停止而非重试，不修改其他服务的超时；等待不延长会话，不承诺强杀已批准事务。

## 单轮操作与记录失效

按固定顺序逐个处理清单范围：

1. 调用原`previewExhibitionReminders`，获得同一只读快照的当前资料、资格、拟新增/拟取消和封套；预检前后全表不变。
2. 若被配置门禁阻止，停止本次调度，不尝试改变开关。没有拟新增且没有拟取消时，只显示必要汇总，不应用、不写审计或生成新本地操作文件。
3. 有变化时，先完整保存私有回执及未决状态，确认可恢复后才调用原`applyExhibitionReminders`；仍使用原事务、原锁序和提交后核实。
4. 服务明确成功返回后，在有效授权及控制锁下追加正常完成审计并核实落库，再将本地操作标为已核实，随后处理下一个范围。完成标记失败/未知也停止并保留证据。正常成功收尾属于本次已授权操作；异常后重启则必须走下述独立恢复动作。每个范围独立提交，不宣称整轮原子性，后面的范围失败不回滚已成功范围或补写剩余范围。

**实施者提议：** 显式启动时一并授权清单内的正常失效核实。退订、拒发、改期、撤下、过窗、公开修订/同意变化等，使原held在下轮预检中成为拟取消；应用仅按原服务取消旧记录，保留历史，不复活终态。非30/7日只能核实取消，不能补生成。

新公开修订在清单内按当前审核结果重新预检；当天仍是合法窗口时，可取消旧修订并生成新修订记录。不自动改草稿、发布资料、迁移跨届同意、纠正翻译日期或修改拒发名单。

订阅总开关、有效隐私、启用语言和维护等现有生成门禁完整保留。新申请暂停不撤销既有同意；邮件开关、供应商凭证和邮件链接核验仍不是本地记录生成前提，且不为调度改写它们。H及所有旧发件入口保持原门禁。

## 并发与锁

建议同一数据库最多一个本地展会调度进程：使用专用连接上的会话级PG advisory lock，第二个进程明确拒绝启动，不等待接管、不争用新任务。锁的标识留实施计划核对现有命名空间后确定。

运行互斥与未决阻断是两项约束。未决状态以当前数据库中持久的调度控制审计为准，启动时在任何新待发写入之前查询；不能以本地目录为空、文件已删或另一台机器没有文件推断没有未决操作。单实例锁释放不等于未决解除。

这里的“全库阻断”针对本功能的所有自动调度启动，不冻结其他业务、内容审核或订阅/退订。手工CLI使用新合法封套仍按原规则执行；已明确作废的未提交调度封套则不能通过手工入口重新写入。

该锁仅避免重复扫描，不替代每次操作的内容726271→业务726281→权限726272→规范邮箱→原始/规范邮箱主题事务锁、唯一键、封套复核或实际鉴权。专用连接不持内容/权限事务锁跨过空闲等待；读写事务在每次操作结束时释放。

手动PR125命令仍可运行。与手工操作或内容/订阅变更竞争时，原服务串行复核；409不被解释为可直接重试。调度锁连接丢失/状态不明时停止后续动作；已有事务依原服务完成或回滚。清理仅关闭本进程连接和资源，不停止其他网站/worker。

**必要的防止旧进程继续写入：** 每次调度应用在原内容→业务→权限锁内复核当前运行身份、未决封套摘要、范围和操作者，之后才进入原生成流程。新的控制状态切换/恢复也按同一锁序串行，不能只在循环外检查一次。旧进程失去单实例连接、稍后才取得写锁时，其已结束/失效的运行身份不能继续提交；不能依赖客户端已经收到停止信号。运行身份是内部关联条件，不是新的登录凭证或裸staffId授权。

## 未决回执与重启恢复

自动循环不能把“结果未知”变成“新一轮再试”。每次可能写入前，先在私有状态目录落盘原回执和操作元数据；数据仅含范围、原操作身份、封套、处理阶段及数据库/清单绑定信息，不含邮箱、订阅ID、密码或明文数据库URL。凭证不写终端、普通日志、Git或.env。

回执沿PR125的暂存写入/同步/关闭后独占发布，不覆盖已有目标。任一保存/同步/关闭失败时不调用应用。无法保证本地持久化的文件系统不允许进入生成步骤。日志展示安全中文汇总，不暴露封套、摘要、私有文件内容或数据库连接串。

随后用既有`audit-events`追加持久的调度未决标记，只存运行关联、原管理员、范围和封套摘要，不存原封套/JWT；确认该标记已真实提交，才可调用应用。控制审计写入本身结果未知时也停止，不把“未收到成功”当未落库。开始/未决/已核实/结束等事件保留，不覆写或删除历史；不新增调度表。只有有效现职管理员可写控制事件，身份失效退出时仅关闭本地资源，不用失效凭证补写停止审计。

409、连接异常、提交后核实失败或应用开始后的异常，均保留原回执及未决状态，并停止整次调度。不会自动重新预检、换封套、重试原应用、清除历史或跳过该目标继续其他写入。

重启先查数据库中的全局未决控制状态，再核对本地证据；有未决时不启动新轮次。更换目录、清单、进程或电脑都不能消除此阻断；本地绑定不符/状态损坏/证据丢失只会转入受控恢复，不会生成或重放原动作。正常查询原回执可使用同一管理员的新有效会话，不允许换人认领原回执。

**必要的恢复补齐：** 增加内部、显式只读的回执核实能力，复用原身份、范围和审计匹配语义。按原封套摘要＋原管理员＋范围核对已提交审计，返回原操作时间与原计数，标明“历史结果，当前资格未检查”；支持合法密钥轮换后的已提交回执。没有匹配审计只返回“未找到可确认的提交，需要人工处理”，绝不生成/取消记录。

不能直接调用现有`applyExhibitionReminders`冒充只读核实：它在未命中历史且封套仍有效时可能实际写入。本批恢复查询必须能在PG只读事务中执行，查验前后全表不变；查询仍要求当前有效的原管理员，撤权/登出403。

普通历史查询及状态查看始终只读，不因看到已提交审计而偷偷清除全局未决标记。解除阻断须是独立、明确的管理员控制动作，原调度进程须已停止且该动作取得单实例锁；没有取得就拒绝，不终止其他进程。

**实施者提出的受控结束规则：** 现职管理员填写核实原因，在原内容→业务→权限锁内重新核对原生成审计。已提交则仅追加“已核实提交”控制事件，不再写待发；没有匹配提交则仅追加“结束未提交操作”事件，同时作废原运行关联和该未提交封套，保留所有证据，不执行原动作。结束后若还需生成，必须明确重启，再根据当前资料预检，不能顺便重跑旧操作。找不到审计本身不是只读确认“绝对未执行”，因此不能自动放行。

结束事件和生成共享锁内复核：旧调用已先持锁时先完成/回滚再核实；结束动作先持锁时，旧调用随后必须因运行/封套已作废而拒绝。已作废且未提交的调度封套通过任何应用入口都不得再次写入；已提交封套的原历史查询保持原管理员、原时间/数量和当前资格未检查语义。

为避免原账号撤权造成全库永久无法恢复，受控结束可由**任一现职管理员**填写原因并执行，记录原操作者和核实操作者；这不开放其他角色、不替他人生成、不让核实者认领或读取他人回执报告。原回执的普通历史查询仍要求原管理员有效会话。原凭证文件缺失也不能用来强行生成，只能按数据库中可信的原未决标记完成控制核实。

本批不提供`force`、清除未决记录、删除历史、自动重新执行或仅修改本地文件解除阻断的入口。上述受控结束仅结束旧动作，不等同于重试、修复内容或打开真实发送门禁。

## 数据与输出边界

只允许写现有`exhibition-reminder-jobs`与`audit-events`中的脱敏生成/调度控制事件；不新增自动调度数据库表或迁移，不扣预算、不占发送槽、不建邮件/营销活动任务、尝试、租约或供应商回执。正常启动/受控结束的控制审计是明确预期增量，稳定运行后的无变化轮次不追加心跳或重复审计。

本地状态文件是恢复证据，不作为全库未决解除、数据库提交、当前资格或发件就绪的权威。私有本地状态需保留；多电脑不能同时运行同一任务，也不通过网盘同步运行中目录。换电脑需要另做受控状态交接和身份核实，不能把另一台机器已有文件当作已完成证据。

每轮输出只含范围数量、当前业务日、当前资料与拟/本次新增取消、跳过/阻止/需核实状态；空闲无变化仅汇总，避免不断打印。历史数量和当前资格分开；现有PR125排除原因分类、U+2028/U+2029标题清理两项轻微遗留继续记录，不混入调度权限或发送能力扩展。

## 本地模拟验收

仅独立随机`hua_subscriptions_*`数据库、虚构管理员与example.invalid；禁止HTTP/fetch/SMTP及真实供应商调用。日期使用数据库北京时间today+30/+7构造真实已审核资料；纯调度等待可注入测试等待器，不给产品暴露日期、跳鉴权或强制应用参数。

验收至少包括：

1. 非local、清库开关、坏JWT/清单/状态路径在Payload初始化前拒绝；已有/缺失数据库无自动建库/同步，额外结构、类型文件内容与mtime不变。
2. 清单空/过大/重复/跨语言/非法标识/额外字段拒绝；只处理固定范围，不混通用主题/其他本届/下一届。运行中改清单或auth文件不扩大范围、不切身份。
3. 真实进程`--once`、多轮定时和明确停止；第一次立即检查、后续等待、无重叠/补tick；同日新确认的订阅下一轮进入。
4. 30/7精确窗口、非窗口纯取消、当天无变化的轮次无新增审计/记录、改期/撤下/退订/拒发/公开改版和终态不复活；在已启动的运行上下文中无变化单轮全表不变，不把启动/正常停止的控制审计误计为轮次副作用。
