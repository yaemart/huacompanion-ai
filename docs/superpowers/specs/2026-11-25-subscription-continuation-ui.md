# 同活动本地续发后台入口

用户在 PR113 合并核对后要求“下一项”，即已说明的后台续发按钮、同源接口与遗留门禁文案。沿用原生实施、既有技术和原地任务分支偏好；不重复请求已明确范围的批准。先完成 H，再做展会日历。

采用现有工作台中的独立小面板，显式勾选确认后复用 resumeMockCampaignRevision。管理员、其他主管及其他角色不扩权；仅 local、本人现职授权、当前新版、来源有效、重新模拟逐语言确认、未暂停取消及原服务全部守卫允许提交。原冻结名单/版本不覆盖，不补新人，不清除、强制重试或真实发送，不自动启动 worker。

新增 continue-revision-local 写动作：只接受 campaignKey/revision/confirmed:true，适配为原服务两字段输入。新增 read-continuation-local 只读收据动作，复用 inspectCampaignMockChecks 的权限/版本及只读事务，精确定位本人当前版已有 continue-local 审计，返回安全收据或 null。独立查询保留原预检协议与单次名单查询；把查询并进预检会扩大前批协议和测试范围，修改原快照 current 则混淆冻结历史，因此选择独立收据。

收据仅活动、当前版、原版、绑定数、续发时间和重放标志，严格检查类型、字段、版本关系、范围1–1000及标准时间，不暴露邮箱/正文/任务/凭证/私有确认。服务查询不写 reset/审计/任务。已保存收据是历史事实，不能替代来源/确认/暂停取消等执行门禁。

工作台从服务器读取收据。只有明确存在原冻结当前版或当前版续发收据时才放开现有占位准备；保留 frozen.current 的原意。续发入口禁用未保存、未确认、未改版、暂停取消、其他操作忙碌或结果未核实状态。请求去重用 ref；请求期间及导航未卸载时互锁保存、确认、准备、领取和控制。正常提交成功重开已保存活动，载入新版任务；无未保存选择可丢。网络/503/畸形收据视为待核实，锁其他写入，只读核实收据；找到则原页展示、继续互锁，用户明确点击重新打开才加载原页面状态（条件变化时确认会失效），无记录才解除锁并要求重新勾选。4xx确定失败保留当前选择，无自动重试或跨版调用。

预检仍只读，文案说明另用续发按钮；原快照与占位/调度遗留“尚未开放”说明调整为本版尚未绑定/原历史保留。客户端由新增收据查询恢复重开状态；不改原槽位/额度/尝试/调度规则。
