# 多电脑开发协作设计

用户已接受会话中提出的协作方案：GitHub 保存共享代码，main 保存已验证版本，每个任务使用独立分支；交接前推送，接手前拉取并核对；数据库、图片与密钥独立管理。

## 方案与范围

采用任务分支与 PR，配合仓库交接文档和自动检查。按电脑长期分支会混合多个任务，直接在 main 并行修改则难以独立验证；本次选择任务分支方案。

在现有干净开发分支中增加协作规则、说明、交接模板、Node 版本文件和 GitHub Actions。保留 Next.js 自动维护的 AGENTS 块，不改业务代码；不搬迁正在运行的本地数据库，也不创建额外工作树或复制运行环境。

CI 使用只读仓库权限、Node.js 24.22.1、临时 PostgreSQL 15。PR 和 main 推送运行；分支无 PR 时只保存代码，不自动重复消耗 CI。迁移与构建关闭 schema push；六组集成测试串行运行并保留当前 local 模式约束。无部署、真实供应商密钥、私有数据上传或自动合并。

交付为可阅读文档、可运行 workflow、已推送任务分支和 PR。实际云端结果需运行后核对；仓库保护规则的强制执行与功能合并不包含在本次自动修改中。
