# 内容标识与「高级」区：内容中心 P1 第一批

状态：2026-11-11 已确认。基线：PR44 已合并，`origin/main` 为 `a295bdea14ad5e35039185e9c9c5ccb052f1b1e6`。
范围：[后台录入界面任务](../../tasks/editor-ux.md)第 5 条第一项，仅内容工作台的新建与编辑入口。

## 编辑怎么用

- 新建指南、展会等内容，填写标题及原有必填资料后即可保存，不用先理解或填写两个标识。
  默认折叠的「高级」区保留内容标识与网址标识，未填时提示“首次保存时生成”，保存后显示实际值。
- 内容标识使用独立编号。网址优先使用标题中可转成小写英数的文字；纯中文等无可用字母的标题使用
  类型加短编号，例如 `guide-4f8c71a2`。自动网址重名时追加 `-2`、`-3` 等，不覆盖原稿；
  最多检查 50 个候选，全部占用时提示在「高级」区换一个值。
- 首页、关于、联系、伙伴、隐私、条款是固定页面。新建时直接选择要编辑的页面，生成对应的标识和网址，
  例如隐私页使用 `page-privacy` 和 `privacy`，也可沿用同页唯一的旧标识。同语言已有页面时提示打开原稿，
  不自动另造网址。已绑定固定页的标识不能用于不同页面，避免跨语言串页。
- 需要自定义时，在「高级」区填入标识。明确填写的值按现有格式校验；冲突时提示，不静默改成别的值。
  已有工作稿的内容标识不能改；曾发布的网址不能改，改标题不会重新生成。普通未发布稿仍可编辑网址。
  未发布的旧手填固定页只有在不会拆开已有配对时才能更换页面。

## 为什么在首次保存时生成

客户端边输入边猜网址可以即时预览，但不能可靠知道其他员工是否同时创建同名内容；标题变动时也容易误改网址。
采用已有保存接口在事务内生成，只为新建且留空的字段补值。服务器按现有唯一规则检查工作稿与正式快照，
旧记录、历史和权限不改。不依赖浏览器列表是否完整，也不会返回用户无权限读取的其他记录资料。

普通内容不按标题猜测中英文关系：同名不代表同一篇。手动沿用已有同类型内容标识仍可配对；固定页面按页面配对。
原手填标识的跨类型跨语言使用不新增限制，不因此形成配对。保存成功后立即采用返回的稿件编号，
列表刷新失败不会退回未保存状态。
已有 AI 转写、政策工作台与专用导入流程沿用各自规则；双语对照、整篇编辑、政策横幅选择和核实日期分后续 PR。
不新增依赖、环境变量、数据库结构或外部服务，不改已有网址或发布／审核权限。

## 验收

- 在隔离库新建纯中文指南，只填正常字段就能保存；展开高级区看两项实际值。
- 英文、带重音字符、重名、长标题、手填冲突和固定页面各验证；并发同名不会覆盖或配错语言。
- 修改标题不改标识；已发布网址仍锁定；同一现有内容标识可按原规则用于另一语言，旧链接仍可访问。
- 验证越权、待审核冻结、历史恢复和固定页面路由。`npm run check` 和相关集成通过，lint 警告不增加。
  桌面和手机视口截图附独立 PR；最终合并由用户决定。
