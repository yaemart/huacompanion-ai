# 阶段 1.5 站内政策到期复核提醒

> 按 executing-plans 执行；规格为 ../../traffic-entry-phase1-plan.md 的 1.5。

目标：仅正式政策在中国日历日截止前 30／7 天生成持久站内待办，重跑/并发不重复。
架构：纯日期规则 + 内容事务内扫描正式快照 + 复用 workflow 集合和 worker。
技术：既有 TypeScript、Payload、PostgreSQL；无新依赖、迁移、外部服务。

约束：本地开发，不部署、购买、接统计；VISA_CHECKER_ENABLED 非 true 不扫描。
沿交接在当前目录独立依赖分支开发，不改 main 或既有交接分支。

- [x] 1. 日期规则：写测试并观察失败，覆盖 31/30/8/7/0/过期/空日期/非法日期与版本键；实现后通过。
- [x] 2. 提醒事务：写真实数据库集成测试并观察失败；实现正式快照扫描、负责人校验、并发幂等和历史保留。
- [x] 3. worker 接入：跳过政策任务的通用到期邮件/升级流程，直接站内通知，不建邮件任务。
- [x] 4. check、相关政策/权限/workflow 集成、构建；本地启动及默认关闭 HTTP 验证；更新交接。

实施决定：幂等键包含正式快照关联工作稿身份、正式 revision、截止日和阈值。
首次补跑进入 7 天窗口时记录 30 天历史任务为已替代，仅通知最新 7 天任务，避免历史通知轰炸。
无截止日不建任务；下架/正式新版替代后旧未完成任务标为系统关闭，历史不删除。
负责人优先采用该政策 content-quality.owner；缺失/停用/失去范围时保留未分配任务，管理员可见并分配。
已人工分配的有效负责人保留；失效负责人清空并留痕。仅任务完成不会改变政策发布/核实状态。
新提醒沿 quality-due 开关；禁用时不生成新提醒。无新界面，复用 /notifications；截图不适用。
