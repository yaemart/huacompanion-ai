# 后台本地活动取消按钮实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. 自行TDD实现，一次独立只读复核，不分派实现。

**Goal:** 获授权主管在本人活动页面填写原因、明确确认不可恢复后，取消未完成模拟任务并查看终态。

**Architecture:** 现有POST增加cancel-local，严格验证显式确认并复用cancelMockCampaign；客户端复用控制区的原因、请求互斥与不确定状态核实，独立折叠区内确认。服务器返回取消回执，原地更新终态，不追加竞态读取或覆盖未保存选择。无新迁移/worker/真实邮件。

**Tech Stack:** Node24.22.1、Next本地route/client文档、React、Payload、PostgreSQL15。

**Spec:** 用户本轮明确要求；已批准群发B及PR95服务语义。基线 `4c3c2031727ff3d346ffd9031467d25d27460224`。

## Global Constraints

- 原独立主题授权、本人和当前版本校验不改。取消不受未保存选择或失效模拟确认阻挡；恢复规则不变。
- 原因非空、最多500；显式勾选“取消后不能恢复；历史和已占份额保留”。API拒绝未确认、额外身份字段、非本地、越权、陈旧版本及不同源。
- 保留历史、已完成记录和份额，取消后旧租约/恢复/冻结拒绝；重复操作不覆盖原原因。沿用PR95事务，不另建活动或归还份额。
- 成功原地进入只读终态；失败保留原因和选择，结果不确定锁定相关操作并核实，不能显示旧状态为当前。
- 本批仅本地模拟，不发真实邮件，不加部署/worker/依赖/环境变量/迁移，原3100/55442、图片、种子不改。
- 业务改动低于400行；lint不超过445；截图/原始报告只在本机忽略归档，未上传要说明。

## Review Focus

1. 已暂停、未确认、脏选择或来源下架仍可取消，取消不被恢复门槛挡住。
2. 只有明确勾选不可恢复后才能提交，原因聚焦和错误提示可理解；取消与暂停表单互不误提交。
3. 服务端不信任确认/身份之外的额外数据，权限与同源门禁不因新action放宽；回执不泄露邮箱和凭证。
4. 提交中所有相关表单互斥；取消已提交但响应丢失后只显示待核实，重读保留输入并进入终态。
5. 刷新和历史快照仍正确，取消后的任何UI/API都不复活旧任务、不改变已占份额。
