# CRM A2：最小员工界面与受控API

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** 客户列表／基本信息、单个操作表单、联系人、关联咨询与派生服务单入口；不做B总览、转交或跟进。
**Spec:** 已批准阶段A及A1a/A1b边界；用户批准A1b合并后实施A2，基线885a7db。

## 实施决定

复用独立CRM worktree/PG15.20/55443，原演示不启动。Node24.22.1，依赖锁未变化。
/crm-center中文员工页、/api/crm GET/POST，只现职admin/manager/operations，内容角色/外部用户拒绝。
页面异步headers按本版本文档；force-dynamic/noindex；API均no-store、nosniff并Vary Cookie/Authorization。
POST先严格同源、16KiB流式限制、JSON/动作白名单，再认证；不允许前端指定actor或绕过权限标记。
API认证后得到的员工对象在模块私有WeakMap绑定请求Headers副本，currentActor在原业务→客户锁后
重新p.auth核实同一真实会话。A1可信内部调用契约保留，不能把重读staff当会话核实。
会话在锁后最后授权决策点有效；之后登出不追溯中止已经批准提交，和原调度边界一致。
新增options只读动作，返回按当前角色/团队过滤的团队、有效运营名称和建档能力，不含邮箱/角色原始数据。
查询参数严格白名单、禁止重复；ID/page/limit只接受规范正十进制，仍复用原严格服务校验。
已知业务错误保留安全中文；意外错误500通用，不返回SQL/栈/凭据；401/403清空客户端敏感已载数据。

列表搜索、分页及active/archived；详情分页联系人/关联/候选，服务单链接打开原business-center。
一个操作表单一次编辑：创建客户／更新资料／创建或编辑联系人／设主／存档／关联／撤销。
表单捕获打开时的客户/联系人/关联版本，刷新不默默换版本或覆盖输入。
提交使用独立operationKey；在请求结果未知时冻结操作正文、保持原键、禁止其他写，只有重试原操作。
首次已知4xx可返回编辑；未知后即使重试4xx仍保留原请求，不假定此前未提交；需明确登录或人工核对。
输入及未决仅页面内存，不进URL/localStorage/日志；离开与刷新有未保存提醒，不能承诺关闭标签后恢复。
刷新/搜索/选客户前明确处理未保存编辑；请求顺序防旧响应覆盖；读取失败不当成空列表，不展示旧客户混合数据。
未授权字段继续省略；旧客户对外授权服务不改，不加force撤销，不开放真实发送。
