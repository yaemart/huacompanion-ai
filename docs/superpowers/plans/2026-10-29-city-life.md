# 城市生活与体验 Implementation Plan

用户已批准对话中的十三项详细方案并要求实施；本文件将第一批范围落实到现有代码，无需再次确认。

**Goal:** 为餐饮、夜生活、文化、运动、家庭场所和活动提供公开展示、内容审核与华伴咨询。
**Architecture:** 复用 ContentBody/内容快照，新增 venue 与 activity 两个内容种类，共用 lifestyle 结构；餐馆专属字段。复用现有咨询 source 校验、权限及 AI 草稿。
**Tech Stack:** Next.js / React / Payload / PostgreSQL。
**Spec:** 本轮用户批准的“城市生活与体验”详细实施方案。

## Global Constraints
八座现有城市；七种现有语言；只公开发布数据；不虚构真实场所；预约提交不等于确认；内部服务商资料不进入公开内容；现有员工不自动获得新板块权限。

## Review Focus
- 活动已结束、取消、满员、过期报名不能提交关联预约。
- 原页面打开后发生修改，旧 revision 必须拒绝。
- 未发布内容、内部 providerRef、其他板块素材不能泄露。
- 餐馆过敏原/清真/语言能力以核实说明呈现，未知不得推断。
- 日期时区、负价格、未知分类、恶意 URL、非法城市应拒绝。

## Rulings
- 本地正在运行的专用开发目录保持原分支就地升级，避免另一个 checkout 与本地数据库/服务错配；先备份再变更数据库。
- 真实首批20–30条资料为内容运营目标，不以未核实资料填充；本轮提供可使用系统与未发布示例，正式采编须逐项核实来源。
