# 客户管理与双侧门户分阶段开发计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 分批交付客户总览、责任跟进、客户登录完善和服务商入驻协作。

**Architecture:** 复用咨询、服务单、客户认证及providers；新增客户业务档案与显式授权关系。
员工、客户与服务商分别检查业务权限。认证复用分批实施，不把多个子系统一次重构。

**Tech Stack:** Next.js、Payload、PostgreSQL；Node.js 24.22.1，以项目锁文件为准。

**Spec:** `docs/superpowers/specs/2026-11-26-customer-provider-platform-design.md`

## Global Constraints

- 本文为阶段级计划，尚非可直接执行的函数级实施计划；不得据此直接写业务代码。
- 每阶段开始前锁定具体接口、迁移和测试断言，形成对应实施设计与逐项计划，批准后执行。
- 先读取`docs/handoff.md`、`docs/multi-computer-development.md`及相关`node_modules/next/dist/docs/`。
- 新任务从最新origin/main建codex任务分支；前一PR合并后再开始下一顺序任务，不叠加PR。
- 现有展会任务分支与未提交稿保持原状；本计划不自动改变其排期或授权并行修改。
- Node.js 24.22.1；源码Prettier目标100、最长200字符；不引入不必要依赖。
- 提交前npm run check与相关集成测试；实际结果写docs/progress.md，交付一页中文小结。
- 权限、报价、客户数据变化必须补测试；真实邮件、部署、购买、自动合并均不执行。
