# CRM B2同团队责任转交 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 管理员/主管显式转客户主负责人及选中咨询，真实HTTP验证原子性、审计及原键恢复。
**Architecture:** crmAction原事务与操作回执，新增严格transferAssignments动作；咨询沿原hooks更新，服务单责任派生。
**Tech Stack:** Node24.22.1、Next/Payload锁定依赖、PostgreSQL15，无新依赖。
**Spec:** `docs/superpowers/specs/2026-11-28-crm-phase-b-design.md`。

## Global Constraints

- 待设计/计划批准及B1合并，从最新main建codex/crm-phase-b-transfers，不叠PR；B3以后批。
- CRM专用PG55443/随机虚构库，原演示不动；旧对外授权不写，团队不得改变，真实发送不启用。
- 当前原生会话与管理角色、业务726281→客户726283锁后复查；READ COMMITTED，无skipAudit/skipWorkflow。
- 同团队现职validOwner；原因10–2000字，最多20咨询、至少一目标、UUIDv4、16KiB，版本不自动覆盖。
- 原A动作与普通后台权限保持；不新增第二套服务单owner，不清空owner或自动回填。

## Review Focus

1. 只选客户与只选咨询分别只改所选，旧咨询负责人失去客户读权但原咨询权限仍按原规则（任务2）。
2. 预览后咨询有新服务单、服务单变版本或旧后台改owner，即使客户revision未变也409（任务2）。
3. 原键成功后关联撤销/换客户、操作者撤权/失效，重放仍按当前范围拒绝且零写（任务2/3）。
4. 20条与21条、重复ID/未知嵌套字段/同键不同顺序：拒绝或规范摘要，不能半提交（任务1）。
5. 多项中最后一项审计/通知失败及COMMIT丢响应：全回滚或原键确认一次，不假称失败后新建（任务3）。

## Task 2：事务内转交与可重放回执

**Files:** Create `src/server/crm/assignments.ts`；Modify `src/server/crm/service.ts`及上述真实PG测试。
**Interfaces:** `prepareTransfer(p,actor,input,req):Promise<TransferContext>`锁后校验所有对象/当前范围，
重放模式只查当前权限/活动关联而不要求旧版本；`applyTransfer(p,actor,input,context,req):Promise<TransferMutation>`。
TransferMutation={result:TransferReceipt,before,after}；TransferReceipt扩展现有CrmReceipt为
{clientID,revision,transferID,transferredClient:boolean,inquiryIDs:number[]}，transferID为实际审计ID。
service负责统一HMAC/actor+key/版本/审计/receipt事务，不能由apply自行COMMIT；可为新动作单独分支审计创建，
原A动作回执和审计形状不变。input摘要规范排序；重放执行prepare的当前范围检查后才返原回执。
新增assignmentHistory(p,actor,input,req):OverviewPage<AssignmentEvent>及GET assignmentHistory/clientID/page/limit，
AssignmentEvent={id,time,actorName,recipientName,transferredClient,inquiryIDs}，只管理角色、当前双范围。
先按Spec第5节投影可见事件/目标再计数分页，无原因/原始JSON/隐藏目标总数。
