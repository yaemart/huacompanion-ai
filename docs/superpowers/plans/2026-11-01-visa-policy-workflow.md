# 入境政策审核发布适配 1.1c1 Implementation Plan

Goal: 把受保护政策主记录接入既有内容事务与审核服务，保持正式快照隔离；下一步1.1c2再补后台字段界面。
Architecture: 新内容类型immigration-policy单独授权，现有员工不自动获权。每个工作流identity拥有唯一policyKey，工作稿只保留policyRef(id/revision)，事实只在政策集合编辑。所有保存/恢复/提交/发布/下架走现有内容锁和事务，沿用贡献人、自审例外及审计。正式快照只复制公开字段，无政策主记录ID/员工ID/内部备注；现有通用公开列表始终排除政策，专用读取在1.1d实现。
Spec: docs/traffic-entry-task.md; docs/traffic-entry-phase1-plan.md; docs/immigration-policies.md。
Global Constraints: 本地先行，不部署/付费/新增依赖；默认开关不变；业务源码目标400行内；无新增any或超200字符行；新迁移先备份和隔离验证；一步一草稿PR依赖PR6；不自动合并。

Design rulings: 沿用已确认的1.1c方案，按计划预留的拆分规则先交事务/权限，字段界面后交；不另建发布状态机。policyKey自动取contentKey:locale，避免跨语言主记录争用或引用劫持。恢复历史必须读取同主记录对应修订的Payload版本；已清理版本则拒绝，不静默替换。后台直接政策集合仍管理员只读；编辑/审核通过持锁服务，下一步再提供字段UI。政策不会被现有AI入口自动生成或采用。核实人必须为有效且获政策授权员工，发布还需审核人明确确认。日期以Asia/Shanghai当天为基准，不自动联网核实事实。
