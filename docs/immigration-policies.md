# 入境政策数据契约与集合（1.1a–1.1c1）

状态：数据契约、受保护集合/版本，以及1.1c1内容事务适配已本地验证。保存/恢复/提交/退回/发布/下架走现有服务；后台字段界面将在1.1c2实现，种子与专用公开读取在1.1d。当前没有可用公开工具，不代表真实政策已核实。政策集合仍仅管理员读取，所有普通写入关闭。

## 当前已实现

`src/lib/immigration-policy.ts` 从Payload生成的`ImmigrationPolicy`字段派生完整发布输入`PolicyPublicationData`、白名单公开输出`PublicPolicyData`，以及无网络/数据库/时钟副作用的校验与投影函数。校验仅用于完整发布数据；集合允许事实待补的部分草稿，审核服务分别处理。关系在发布契约中收窄为员工ID，口岸数组行规范化为label字符串数组；并非把带关系的原始集合记录直接公开。内部备注兼容Payload的null空值。

字段为国家代码及中英名称、四类政策、最长停留天数、生效/截止日期、口岸区域条件、官方来源、最后核实日、核实人员工ID、公开说明和内部备注。截止可为空，公开投影统一为null，不表示政策永久有效。

日期采用YYYY-MM-DD日历日，调用方显式传入中国当天日期；不取访问者浏览器时区，不把UTC时间戳截取当作中国日期。校验拒绝不合法日期、截止早于生效、未来核实日、不合法停留天数/核实人、带账户信息或非HTTPS的来源URL；240小时过境必须填写口岸/区域条件。不会据此计算240小时出境期限或承诺入境资格。

国家代码当前校验两位大写形状，**不等于确认ISO代码已分配**。国家代码实际归属、来源是否官方、政策条件是否准确都必须由工作人员核实后审核；本轮不下载国家表、不请求官方站点，也不写死政策数据。测试中的国家、来源和日期组合完全为虚构夹具。

公开投影显式列字段，排除核实人、内部备注以及输入中所有额外字段，复制口岸数组避免通过返回对象修改输入。该函数不验证调用者身份或发布状态；后续公开读取必须先从正式快照读取并检查开关，不得把草稿传入这个函数就视为可以公开。

## 集合与工作流映射约定

1. `ImmigrationPolicies` 是唯一的结构化政策录入主记录，包含核实人及内部备注并保留版本；不允许绕过服务直接CRUD。1.1b已生成真实Payload类型，使用Pick/NonNullable派生契约，未手改生成文件或保留重复Schema。
2. 既有 `content-drafts` 承载政策的工作流身份、贡献人、审核状态和修订号；其JSON正文只引用政策主记录及政策修订，不作为第二个可独立编辑的政策字段副本。政策字段保存与工作流修订在同一内容事务中完成；提交后锁定对应政策修订，后续编辑走原退回/重提流程。
3. 审核发布时在同一事务重新核对主记录修订、范围权限、核实信息、来源及自审限制，再把公开白名单政策字段复制到 `content-published` 的正式快照。公开读取只读该快照；草稿改动、主记录新版本和内部备注不能改变已发布结果。下架撤销对应快照。
4. 内容工作台与政策集合界面都调用同一保存/提交/审核服务，不分别维护发布状态。未授权板块不自动授予现有员工；直接REST/GraphQL/Local API和历史版本访问均须受同一边界约束。
5. 公开快照沿用 `publicationRevision`/`publishedAt` 外层元数据；主记录ID、员工ID和内部备注不因关联关系被depth展开公开。本轮已有真实权限、并发和草稿隔离测试；1.1d再实现专用公开读取，不能通过通用内容列表暴露政策。

## 1.1a 内容服务类型整理（历史）

`src/server/content/service.ts` 使用生成的 `ContentDraft`/`ContentPublished` 与 `PayloadRequest`，操作字段用unknown，原校验后才使用正文。JSON字段只在验证过的内容写入边界进行明确类型转换；`allSnapshots` 的既有受信正式数据在本模块按生成模型定义快照类型。此轮不修改其查询/过滤规则、不增加新内容类型、不放宽权限或更改全局内容锁。

## 1.1b 集合与开关

集合slug为`immigration-policies`，数据库名`imm_policies`；使用独立口岸子表及版本表，最多保留30个版本。`policyKey`唯一，工作状态默认draft、revision默认1；状态和修订字段只读。日历日期为文本YYYY-MM-DD，避免日期控件自动时区转换；完整合法性在后续发布服务调用契约校验。当前没有自动发布或公开查询路径。

匿名、普通编辑/审核/运营和停用员工不能读取记录或历史。有效管理员可读取，但不能用REST/Local API（overrideAccess=false）创建/修改/删除/恢复版本。受信内部Local API可显式overrideAccess用于测试及后续持锁服务；它不是外部请求可选的绕过参数。GraphQL仍全局关闭。

`VISA_CHECKER_ENABLED`默认关闭，仅字面`true`开启本阶段的后台导航显示；不改变上述权限，也不会凭此增加一个尚不存在的工具。配置后需重启Web。本机只在截图进程临时传入true，之后已恢复默认；不修改用户.env。公开开关后续由工具路由/投影/SEO共同消费，B确认前不在公网开启。

## 1.1c1 内容事务与权限适配

内容类型新增immigration-policy，现有员工不自动授权，管理员沿用原设置显式授权。mutateContent的save接收独立policy对象：事实字段白名单，口岸条件为字符串数组、核实人为员工ID；支持部分草稿，拒绝id/status/revision等工作流字段。body内伪造policy或policyRef不会被采用。主记录policyKey自动为contentKey:locale，工作稿JSON仅保存真实policyRef的id/revision，没有第二套事实副本。

所有操作复用内容事务和726271锁；政策操作随后按既有内容→员工顺序取726281锁，重新读取操作者当前角色/板块授权。发布时核对核实人有效且有政策授权，明确要求policyReviewed=true及完整日期/来源/条件校验。核实人ID只是工作人员声明，来源权威性及现实政策仍需人工确认，不由格式校验背书。审核、自审例外原因和审计沿用现有规则，未放宽旧板块权限。

提交后原待审冻结生效；保存、提交、发布和下架重新核对政策归属及修订。历史恢复读取相同主记录对应修订的Payload版本，产生新的工作修订；历史被30版上限清理时拒绝409，不用当前值冒充历史。新草稿不改旧正式快照。发布复制publicPolicy白名单到content-published，排除政策主记录ID/核实人/内部备注；工作状态、快照、事件与工作稿修订一起提交或回滚。

政策工作稿beforeChange要求内部事务上下文，既有AI采纳入口没有该上下文，不能覆盖政策工作稿；未新增政策AI能力。正式快照当前也不进入listPublished，因此现有内容API、sitemap等通用入口不公开政策，临时把VISA_CHECKER_ENABLED设true也不会解锁尚未实现的专用工具。1.1c2补字段编辑、受控读取及审核确认界面；本步没有新可用界面，桌面/手机截图不适用，1.1b只读结构截图保留为历史证据。

迁移20261101_091015_immigration_policy_workflow只新增员工板块枚举值，不修改现有授权；down先检查政策授权，有则拒绝，须显式处理授权后才能回退。测试命令test:policies:workflow、test:policies:workflow:http、test:policies:workflow:migration。克隆测试需要本机升级前备份.local/policy-workflow-before/database.dump，或POLICY_WORKFLOW_BACKUP指定路径，只恢复到随机新库。本机升级前66表，克隆和本机up均核对原列数据指纹一致，未改local迁移标记；其他电脑也先停三个进程并自行备份，勿直接down切分支。
