# 入境政策数据契约（1.1a）

状态：仅类型与纯函数基础，尚无政策集合、迁移、录入界面、公开数据接口或查询页面。不得将此PR视为政策事实核实或工具上线。新增业务能力均未启用。

## 当前已实现

`src/lib/immigration-policy.ts` 定义完整发布输入 `PolicyPublicationData`、白名单公开输出 `PublicPolicyData`，以及无网络/数据库/时钟副作用的校验与投影函数。校验仅用于完整发布数据；草稿允许资料待补，后续CMS接入时分别处理。

字段为国家代码及中英名称、四类政策、最长停留天数、生效/截止日期、口岸区域条件、官方来源、最后核实日、核实人员工ID、公开说明和内部备注。截止可为空，公开投影统一为null，不表示政策永久有效。

日期采用YYYY-MM-DD日历日，调用方显式传入中国当天日期；不取访问者浏览器时区，不把UTC时间戳截取当作中国日期。校验拒绝不合法日期、截止早于生效、未来核实日、不合法停留天数/核实人、带账户信息或非HTTPS的来源URL；240小时过境必须填写口岸/区域条件。不会据此计算240小时出境期限或承诺入境资格。

国家代码当前校验两位大写形状，**不等于确认ISO代码已分配**。国家代码实际归属、来源是否官方、政策条件是否准确都必须由工作人员核实后审核；本轮不下载国家表、不请求官方站点，也不写死政策数据。测试中的国家、来源和日期组合完全为虚构夹具。

公开投影显式列字段，排除核实人、内部备注以及输入中所有额外字段，复制口岸数组避免通过返回对象修改输入。该函数不验证调用者身份或发布状态；后续公开读取必须先从正式快照读取并检查开关，不得把草稿传入这个函数就视为可以公开。

## 后续集合与工作流映射约定

1. `ImmigrationPolicies` 是唯一的结构化政策录入主记录，包含核实人及内部备注并保留版本；不允许绕过服务直接CRUD。1.1b生成真实Payload类型后，用其字段Pick/Omit替换本轮独立业务类型，避免手改生成文件或保留重复定义。
2. 既有 `content-drafts` 承载政策的工作流身份、贡献人、审核状态和修订号；其JSON正文只引用政策主记录及政策修订，不作为第二个可独立编辑的政策字段副本。政策字段保存与工作流修订在同一内容事务中完成；提交后锁定对应政策修订，后续编辑走原退回/重提流程。
3. 审核发布时在同一事务重新核对主记录修订、范围权限、核实信息、来源及自审限制，再把公开白名单政策字段复制到 `content-published` 的正式快照。公开读取只读该快照；草稿改动、主记录新版本和内部备注不能改变已发布结果。下架撤销对应快照。
4. 内容工作台与政策集合界面都调用同一保存/提交/审核服务，不分别维护发布状态。未授权板块不自动授予现有员工；直接REST/GraphQL/Local API和历史版本访问均须受同一边界约束。
5. 公开快照沿用 `publicationRevision`/`publishedAt` 外层元数据；主记录ID、员工ID和内部备注不因关联关系被depth展开公开。后续1.1c/d必须补真实权限、并发和草稿隔离测试，此处没有冒称完成。

## 本轮内容服务类型整理

`src/server/content/service.ts` 使用生成的 `ContentDraft`/`ContentPublished` 与 `PayloadRequest`，操作字段用unknown，原校验后才使用正文。JSON字段只在验证过的内容写入边界进行明确类型转换；`allSnapshots` 的既有受信正式数据在本模块按生成模型定义快照类型。此轮不修改其查询/过滤规则、不增加新内容类型、不放宽权限或更改全局内容锁。

后续1.1b为独立PR，负责实际集合、版本、默认关闭开关、生成类型及安全迁移。本轮无需迁移，不启用外部统计，不需要账户、费用或新增包。
