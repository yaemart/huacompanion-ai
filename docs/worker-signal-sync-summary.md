# 独立 worker 处理中信号验收

PR106合并后，基于最新main6645d96补强[PR107](https://github.com/yaemart/huacompanion-ai/pull/107)，
本批补齐此前信号时点测试的轻微待办。生产worker及原有业务规则不变，仅修改测试与交接。

测试现在先让当前结果审计事务阻塞在专用数据库屏障，再通过独立进程标记和数据库阻塞关系确认实际到达，才发送信号。
不再从开始尝试记录或固定sleep推测“处理中”，也不在已完成回执出现后才发送TERM。

- SIGKILL：结果仍未提交时强杀，释放屏障后等待该worker数据库会话全部退出，再核对结果回滚。
  原任务只有1次尝试、1次开始审计、没有结果审计；租约到期仍按原规则推导待核对。
  用模拟完成和结果不明两种结果重启，均没有重领或补结果，全库指纹与待核对汇总保持。
- SIGTERM：事先准备两项可领取任务，确认第一项正在结果事务中，再发送信号。
  测试observer只报告事件监听器本轮已执行，不实现停止。收到报告后仍确认同一事务阻塞，才释放屏障。
  进程完成第一项、仅一份完成回执并退出0；第二项没有领取凭证、尝试或领取审计。
  随后显式启动新进程，可以正常处理第二项，证明不是原本没有可处理任务。

三种受控反例分别验证：绕过屏障会因未观察到结果事务阻塞而失败；TERM立即退出会因处理中信号确认失败而被拦截；
TERM继续运行会因领取下一项而失败。每次反例均在随机测试库运行，改动文件逐字恢复，不进入提交。
