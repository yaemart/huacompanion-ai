# 本地模拟任务抢占与租约：亲测指南

本批验证多个进程争同一任务，以及进程中断后的恢复。只处理已取得模拟份额的虚构任务，新增的“完成”只是数据库模拟标记，不是发过邮件。没有新页面、按钮或后台常驻进程。

## 怎么亲测

使用 Node24.22.1，保持本机演示 PostgreSQL 运行，在项目目录执行：

```sh
npm run test:subscriptions
```

命令新建随机临时数据库、应用迁移并运行21组检查，结束后清理测试库和子进程。无需手动修改原数据库或等待一分钟，也不要重置3100演示。成功时最后会看到：

```text
PASS 本地模拟任务租约：双进程竞争、中断过期恢复、旧凭证拒绝、完成幂等、权限与审计回滚
```

这条检查实际执行以下步骤：

1. 启动两个独立子进程，确认不同进程编号，同时竞争同一任务；一方取得租约，另一方只得到“忙碌”，拿不到凭证。
2. 终止取得租约的进程；租约未过期时，另一方仍不能抢占。
3. 仅在随机测试库把租约设为过期，再由剩余进程恢复；新凭证与旧凭证不同，旧持有者无法提交。
4. 剩余子进程与父进程并发提交完成，最后只保留一条完成记录和一条完成审计；重复提交不会重复完成，已完成任务不能再被抢占。
5. 验证审计提交失败整体回滚、越权/撤权/退订/同意或语言变化拦截、原占位份额不重复增加、单封邮件队列不变。并发退订用正式流程相同的邮箱/主题锁和未提交事务作屏障；等待退订提交后，模拟完成必须被拦截。

失败时请反馈命令、时间、最后的错误文字或截图；不要附 `.env`、密码或凭证。首次缺数据库时按《本地测试指南》启动演示数据库，再重试。

## 边界和数据变化

租约先采用与现有单封邮件任务一致的60秒，使用数据库时间；到期后重新取得租约，慢的模拟处理需要重做。旧进程可能仍在执行计算，但不能凭旧凭证提交完成。本批只保证模拟完成标记不重复，不能据此承诺真实外部操作绝对只执行一次。

新增私有租约表，按原占位唯一，保留原额度历史；有记录时拒绝回退以免丢失。本次迁移只应用随机测试库，原3100/55442、图片和种子保留；原演示库升级仍需数据库与图片配套备份后迁移并重启。无新环境变量或依赖。

真实投递的幂等、结果不明、共用尝试/冷却、全站传输限额、优先级和余额核对仍待后续。真实邮件、AI、语音、通话及正式评分保持关闭。原始日志仅本机忽略归档，无本批浏览器或真实手机验收。
