# 政策群发 B2a：草稿版本与双语预览

本批基于 PR83 合并后的 main，先完成可独立验收的数据服务。授权主管可以保存自己的活动草稿；每次保存保留上一版，不能覆盖其他主管的活动。固定中英文预览只引用已发布的共用事实政策，显示来源和核实日期，不包含内部备注。

政策改版、下架、过期或说明失效后，旧草稿会标为需要重新选择；相同事实重新发布成新版本也会失效。预览不自动换成新正文。未齐备某语言的整份资料时，该语言订阅者被排除，不改用另一种语言。

**本批没有后台操作入口，也没有测试发送、确认发送或邮件队列。** 页面操作留到下一个 PR，真实邮件继续关闭。

## 怎么亲测

1. 保持现有演示 PostgreSQL 运行，使用 `.nvmrc` 指定的 Node 24.22.1。在项目目录运行 `npm run test:subscriptions`，不用重置演示数据。
2. 命令会新建随机命名的独立临时库，完成迁移和虚构数据验收，再自动删除；原演示库和图片不变。预期共 14 组 `PASS`，最后两组为“群发草稿私有存储、版本唯一和无损迁移”和“群发草稿追加版本、当前授权、双语事实配对、预览人数、来源失效与审计原子性”。
3. `npm run check` 已通过：353 项单元测试、类型检查、格式及行长检查通过；lint 为 0 错误、445 条既有警告，未增加。浏览器易用性和真人测试本批尚未进行，不据此填写客户场景或编辑场景通过。

人数是按当前确认状态、隐私版本及语言计算的**预估**，不包含邮箱，也不是实际可发快照；拒发名单、频控、额度及发送前复查还在后续任务。此阶段不能用于真实发件。

## 环境与下一步

新增私有表 `subscription_campaign_drafts` 和迁移 `20261120_110000_subscription_campaign_drafts`，有草稿时拒绝直接回滚删表；没有新增环境变量、依赖或演示种子。本机 3100 演示副本未升级，不能在那里找到本批功能；以后升级须先配套备份数据库和图片、核对迁移并重启。

合并后下一批接入授权管理和活动草稿页面，再做本地模拟测试与手动确认条件。真实发件仍需单独核实账户、内部测试收件人、名单、规模和费用并获得授权。
