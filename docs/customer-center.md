# Verified customer center

`/{locale}/account` supports zh/en/es/fr/de/it/ar. Verification is disabled by default in the `customer-settings` global. Enable it only with the workflow email integration configured (`WORKFLOW_MAIL_ENABLED`, `WORKFLOW_MAIL_API_KEY`, `WORKFLOW_MAIL_FROM`). Existing sessions require the global to remain enabled; temporary mail outages do not invalidate existing sessions.

The request endpoint returns the same success structure for new/existing accounts, email limits, and delivery failures. Invalid email format is rejected. There is no public account lookup. A 256-bit code is sent by the explicitly configured mail provider; only its SHA-256 hash is stored. The browser receives a separate random challenge handle. A challenge lasts ten minutes with at most five guesses, is consumed once, and is invalidated if delivery is not confirmed. Requests are capped at three per email and 100 overall in fifteen minutes under a database lock; forwarded IP headers are not trusted. Verification email, customer portal controls and progress labels are available in all seven languages.

Verification creates a seven-day random session. The database stores a hash, and the browser receives an HttpOnly, SameSite=Strict cookie. Secure is required except explicit local HTTP development. Logout revokes the server record. All mutation routes require the configured origin and bounded request bodies. Raw codes and session tokens must never be logged or added to analytics. Production session configuration requires HTTPS.

Email equality never associates historical inquiries or anonymous chat cookies. Operators use the inquiry workbench's verification form to record identity evidence before explicitly linking a verified customer. Current inquiry access is checked again in the write transaction. Links store the staff actor, reason and timestamp; revocations retain the original evidence plus a separate revocation record. A revoked link cannot currently be reactivated through the UI. Linked inquiries are checked on every customer read; business operations also reload the account and session. Optional conversation links require staff access to the conversation and its existing inquiry association; only public message text is returned, without internal notes, visitor secrets, draft proposals, or private audio URLs.

`customerSession(p, headers)` returns the account and an internal `customerSessionID` marker. API callers must pass this result to business operations so concurrent logout is rechecked. Trusted internal service tests may pass an account directly without a session marker. `customerOwnsInquiry(p, customer, inquiryID, req?)` returns true or throws 404. `customerLinkedInquiries(...)` returns allowed inquiry IDs. All customer transactions acquire the business coordination advisory lock 726281, then customer lock 726283, matching quote confirmation and assignment changes.

Tests: `node --experimental-strip-types --test tests/customer.test.ts`; `npx tsx tests/integration/customer.ts` runs serially against the local fixture database. Integration writes/settings are rolled back and all mail uses injected memory adapters. Never enable real mail as part of tests. Customer auth collections deny generic REST/GraphQL CRUD; only the server services operate them.

The portal also displays persisted business notifications and unread counts in all seven languages. Marking a notification read rechecks the authenticated session and current inquiry association inside the same transaction. Customer-setting changes acquire the coordination lock so disabling the center is serialized with quote confirmations. Linking and revoking reload the acting staff record after acquiring that lock; a stale login does not retain disabled or removed authority.

The rollback-only integration harness wraps real Payload operations in PostgreSQL savepoints. This is necessary because Payload calls `req.payload.db.rollbackTransaction` directly on expected access-denied reads, bypassing a proxy adapter. Tests verify that the original settings and fixture counts are restored after rollback.
