# 本地亲测 · 订阅确认邮件与一键退订

## 这一批做了什么

访客同意订阅后，任务进入后台发件队列。单封中英文邮件说明订阅主题。收件人点确认后，该主题才生效。邮件正文和支持一键退订的邮箱客户端都可退订。

发件服务超时或要求稍后再试时，后台沿用同一封邮件和同一个发件编号。每个邮箱跨主题共用 15 分钟间隔和滚动 24 小时五次上限，重试也算一次。单封邮件最多尝试五次，并在入队 23 小时后停止。发件服务确认接收仅表示请求被接受，邮箱实际送达要另行验证。

## 怎么亲测

1. 合并后按[本地测试指南](local-testing-guide.md)启动或重启演示站。使用 Node 24.22.1。在项目目录执行 `npm run test:subscriptions`。
2. 最后一组应显示「PASS 单封确认邮件、中断恢复、发送限流和客户端一键退订」。测试会使用虚构邮箱，在临时数据库模拟发件超时、邮件服务限流、重试和进程中断。使用同封邮件确认后，通过客户端退订命令撤销，再订阅后旧退订凭证不会影响新订阅。
3. 核对其余四组也显示 PASS。测试结束会删除临时数据库，3100 演示资料保留。日常测试使用模拟发件，保留发件开关默认值即可。

## 真实发件待确认

真实发件继续关闭。启用 `SUBSCRIPTION_MAIL_LINKS_VERIFIED` 前，需要核对收件端的 DKIM 签名覆盖两个退订邮件头，关闭发件域名的点击跟踪，并让站点网关和监控对一键退订地址中的凭证脱敏。Resend 的请求日志可以保留原始请求正文，需另外核实供应商对凭证的处理，或由项目负责人明确批准处理边界。当前 Render 限制试运行方案继续禁用发件。 [RFC 8058](https://www.rfc-editor.org/rfc/rfc8058.html) [Resend 域名设置](https://resend.com/docs/dashboard/domains/introduction) [Resend 请求日志](https://resend.com/changelog/logs-api)

暂停新订阅和确认邮件时关闭 `SUBSCRIPTION_REQUESTS_ENABLED`，既有退订入口仍可用。群发继续留在停止点 C。
