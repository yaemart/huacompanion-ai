# 本地投递回执与营销拒发基础

本批让管理员的内部本地演练服务记录“收件服务器已接收”“硬退信”“投诉”三类模拟反馈。供应商接受请求仍是原模拟尝试结果，不等于服务器送达，更不等于用户已阅读。普通永久失败不会自动当作硬退信。本批没有后台按钮、公开HTTP回调、真实发件或供应商验签适配器。

反馈必须绑定已经开始的虚构邮箱任务、原尝试及活动，时间不得早于尝试或晚于当前数据库时间。同一事件编号和内容重放不追加记录/审计；同编号改目标、类型或时间会拒绝。邮箱已改变时仍按原任务摘要核对，拒发只作用于原邮箱，不误伤新地址。

硬退信或投诉会在同一事务记录独立营销拒发和审计。迟到的送达不会解除拒发，普通重订、另建活动和改版续发也不能清除它。新冻结、准备、调度、领取和开始尝试复用原资格守卫排除拒发。只读预检只反映资格，不顺带取消任务。已开始尝试的结果仍须通过原同意、活动和有效凭证守卫记录，拒发不吞掉结果；所有新尝试和重试继续拒绝。已有尝试正文、唯一键、结果、同意历史和已占额度保留；已经开始的外部操作无法据此撤回。

内部服务只允许local下的现职管理员调用，两个新集合默认拒绝直接增删改查且没有集合HTTP端点；主管原本的汇总权限不扩展。原权限、预算/冷却、限速、邮件优先和重试保留；不改确认或用户主动申请的单封资料邮件，不提供清除、恢复拒发或强制重试。

新增迁移20261125_120000_subscription_campaign_feedback及生成类型，仅独立随机测试库应用；非空回执/拒发表拒绝回退。不需要新增依赖或产品环境变量，未升级本机已有演示库，不能直接重启使旧库自动同步。需要接入演示时先备份数据库与图片、停Web/worker、迁移并重建；不要local:reset。

本批为内部服务，没有新增人工页面测试入口或截图。开发者在隔离PG15/虚构资料下验证原任务绑定、字段/时间/现职权限、重复/冲突/乱序、回滚、跨活动/重订/续发拒发、只读指纹和事务竞争；最终完整检查及独立复核见[交接记录](handoff.md)与[草稿PR117](https://github.com/yaemart/huacompanion-ai/pull/117)。原始日志仅本机.local/subscription-local-feedback，不上传凭证或数据库。
