# 活动草稿：本地模拟测试与确认

本批可以生成中英文模拟邮件，并逐语言确认可读。固定收件人为 `preview@example.invalid`，**没有实际发信**；完成模拟确认也不代表可以真实群发。主管仍只看自己的活动和汇总人数，不取得邮箱名单。

## 启动与关闭

使用 Node 24.22.1，保持演示 PostgreSQL 运行，在项目目录执行：

```sh
npm run test:subscriptions -- --preview
```

打开 `http://127.0.0.1:3186/admin`。终端显示本次 `preview-accounts.json` 的完整位置，里面有管理员、两位主管和运营的随机测试密码。预览使用独立临时库，自动应用新迁移，不升级原 3100 演示或重置旧数据。关闭时按 Ctrl+C；临时库、账号和副本自动清理，再启动即恢复初始状态。

## 建议亲测顺序

1. **管理员**登录，从仪表板打开“政策群发草稿与主题授权”，给“预览主管1”授权政策更新操作权。管理员本人做活动也需要明确授权。
2. 登出，换**主管1**。勾选一条虚构政策，保存草稿。下方应显示“尚无有效模拟测试”，不能直接确认。
3. 点“生成本地模拟邮件”，检查中文和英文正文、来源及核实日。两封都标明未实际发送，收件地址是虚构地址。只勾一种语言不能提交；两种都确认可读后，点“记录本地模拟确认”，应显示完成但未发送。
4. 再勾另一条政策，旧完成提示应消失，要求先保存；保存为新版本后，必须重新生成模拟邮件并逐语言确认。请求处理期间，政策选择及保存会暂时锁定，避免修改丢失。
5. **权限**：主管2即使获授权也不能打开主管1的活动；运营不能操作。管理员撤销主管1授权后，主管1重开旧链接应被拒绝；重新授权也必须重新测试。
6. 缩窄窗口检查按钮、正文换行和勾选。反馈请记录账号角色、操作步骤、预期、实际结果及截图。不要附账号密码。

来源改版、下架、过期、授权版本或发件配置改变均使旧结论失效；系统观察到变化后，即使恢复原配置，也不能复活旧确认。来源改版及配置变化已有隔离集成测试，亲测时无需开启邮件开关。
