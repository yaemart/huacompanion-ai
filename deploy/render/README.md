# Render 受限试运行准备包（1.7 本地部分）

本目录是可审查的配置与操作方案，**不是已部署环境**。未创建账户/资源，未发生费用，未启用统计。应用1.1—1.6仍依赖未合并PR链；1.7任务分支基于PR17，实际部署必须选定经过验证的完整提交。

## 配置模板与费用确认

`blueprint.json` 使用 JSON（YAML 的兼容语法），在 Render Blueprint 创建界面的自定义文件路径选 `deploy/render/blueprint.json`。放在非默认路径，不能误以为推送代码就部署。模板已按官方 JSON Schema 本地校验，但平台账户、地域容量、资源名称冲突和实际报价仍须在创建前核对。

| 资源            | 模板建议                              | 用途 / 尚待确认                                          |
| --------------- | ------------------------------------- | -------------------------------------------------------- |
| Web             | Docker / starter / Singapore / 单实例 | 网站、后台、图片；规格可能需根据内存实测提高             |
| support worker  | Docker / starter / Singapore          | 初始待命，不跑任务，待命资源也可能计费                   |
| workflow worker | Docker / starter / Singapore          | 初始待命；确认配置后处理站内任务                         |
| PostgreSQL      | 15 / basic-256mb / 5GB / 同区         | 独立空库，不导入本机虚构数据；外部IP列表为空             |
| Web磁盘         | 1GB，`/app/.local/content-media`      | 仅网站可读写，不能与worker共享；空间告警、异地副本另确认 |

`autoDeployTrigger=off` 禁止后续Git推送自动部署，**不阻止创建Blueprint时发生首次部署和收费**。因此当前不能点击创建/Apply。费用确认须包括三项常驻计算、数据库/存储、带宽、备份保存、恢复演练临时资源及工作区套餐；以平台当天最终报价和你批准的月费上限为准，不把模板规格视为已购买或最低成本承诺。

模板暂固定本任务分支；部署前将三个服务一起指向已批准发布分支/同一提交。所有部署手动触发；不要让三个服务各自漂移到不同代码版本。

## 账号和配置清单

- Render账号/工作区与最小必要维护邀请；私有GitHub仓库授权（无需在聊天发令牌）。
- 选择地域、资源规格、总月费上限；审批恢复目标和备份保存的费用。
- `APP_URL`：完整HTTPS源地址，不带路径/参数；可先用Render平台地址，后续域名和DNS单独确认。
- `PAYLOAD_SECRET`：环境组生成，三个服务共用；不要轮流生成不同值。
- `TRIAL_ACCESS_USER`：3—64位字母、数字、下划线或连字符；`TRIAL_ACCESS_PASSWORD`：平台生成随机长口令，仅通过安全渠道给受邀人员。
- 后台首位管理员、隐私经营主体、告警联系人、备份/恢复负责人。
- 邮件/AI/语音/通话账户不属于此次前提，保持空白和关闭，不创建这些账户。

整站口令是试运行第一道门，不是员工角色，也不提供内容编辑权限；进入后台后仍须员工登录。Basic口令只允许在HTTPS托管环境使用，本机HTTP仅限回环测试。不要把口令写进URL、截图、GitHub或日志。浏览器可能缓存口令，结束测试可关闭私人浏览窗口；撤销访问通过轮换平台口令并重启服务。受限阶段主要通过后台Cookie登录，Bearer API集成需之后另行设计，不绕过入口口令。

## 服务和存储契约

`node scripts/render-runtime.mjs web|support|workflow --check` 只检查环境字段，输出缺失字段名，不打印密钥，不连接数据库。正常启动会验证trial、HTTPS源地址、强口令、关闭收录/表单/邮件/AI。Render trial即使误设关闭入口门禁也仍要求口令；缺口令拒绝访问。

三个服务共用数据库和Payload密钥。数据库迁移只由Web的pre-deploy执行；worker默认 `TRIAL_WORKERS_ENABLED=false`，常驻待命且不连接业务库，收到退出信号可停止。初次迁移、后台初始化与功能设置通过后，分别手动改为true。待命或进程存在不等于worker已处理任务，须检查真实任务与日志。

Web磁盘只保存内容图片。当前语音音频存储在数据库，不迁移其存储；客服、语音、通话及模型都不在本次启用范围。以后任何worker需要读取图片文件时必须先改为受控共享存储方案，不能用同名磁盘冒充共享盘。磁盘只能运行时访问，pre-deploy/one-off job无法操作该图片盘；需要图片的维护通过Web实际实例的受控Shell/SSH进行。带磁盘服务更新有短暂中断，不能宣称零停机。

`/api/health` GET/HEAD仅返回`ok`，无数据库/账户/内部状态，是平台存活探针，不证明数据库、worker和功能就绪。其余页面、API、静态文件和图片优化均要求口令，拒绝响应不缓存并标noindex。`TRIAL_MAINTENANCE=true`时应用请求503，健康探针仍200以保持维护终端可用。维护模式也不阻止CLI或worker写入，必须另停所有写入者。

受限模式限制：Next图片优化器内部取图不带入口口令，经实际HTTP验证即使外层已认证仍返回401；当前页面使用普通图片，无 `next/image` 使用。后续若引入优化器需单独适配并测试，不能豁免媒体访问保护。

## 首次受限部署（仅账户与费用批准后执行）

1. 确认上述费用和访问权限、选择已验证提交，核对模板；设置平台秘密。独立试运行库/盘为空，不导入本机测试管理员或虚构内容。
2. 手动创建资源，Web pre-deploy先跑 `npm run payload -- migrate`；两个worker保持待命。迁移失败停止，不反复点部署或自动down。
3. 确认Web磁盘写权限、挂载路径和持久性；检查首页无口令401、有口令200、后台仍需登录。`/api/health`200不算这一项完成。
4. 在Web维护终端临时设置BOOTSTRAP_ADMIN_EMAIL/PASSWORD/NAME（真实负责人通过平台秘密输入），先 `npm run bootstrap:admin` 预览，再 `npm run bootstrap:admin -- --apply`。仅空staff集合可创建，不会覆盖已有账户。完成后移除临时秘密，负责人更换初始密码。
5. 运行 `npm run trial:configure` 预览、再 `npm run trial:configure -- --apply`，确保客服/客户中心等后台开关关闭。外发/模型的环境项仍为空；不是仅靠隐藏导航。
6. 先完成下述配套备份与恢复准备，再启用两个worker，核对均在正确版本和数据库运行。设定时区、日志及告警负责人，监测失败而非只看进程存在。
7. 受邀员工通过门禁后录入少量真实资料、审核发布；可在受限环境将VISA_CHECKER_ENABLED设true验收。禁止收录、表单收集和外发仍保持关闭。开启公网入口须停止点B确认，不能直接撤掉访问口令。

## 每日备份、配套恢复和升级回滚

真实每日自动备份**尚未配置或验证**，不得因此开始存放不可替代内容。Render数据库恢复能力与磁盘快照不是同一时点的配套备份；官方保留策略需要按最终套餐核实。落实前由指定负责人保存人工配套副本；正式内容录入前必须确认自动方案、保存位置/加密/权限/保留天数以及可接受丢失时间和恢复时间。

建议部署前审批一个每日维护窗口，暂以24小时为待确认的数据丢失上限：

1. 将Web**当前已运行提交**重新部署为维护模式；pre-deploy只应看到已应用迁移。不要在此步切到新代码。停止两个worker和其他CLI写入，等待正在进行的请求/事务完成；核实应用503、进程状态与无写入。
2. 在同一无写入窗口导出PG15完整数据库，并从实际Web实例归档整个`.local/content-media`。备份仅通过已授权平台导出/Shell/SSH或管理员PG客户端完成，不假定镜像内有pg_dump（本镜像未安装）。若需要外部DB连接，只在批准后短时允许维护者IP，用TLS，完成撤销；不要改为全网开放。
3. 保存唯一备份批次、代码SHA、迁移列表、UTC起止时间、库/盘来源标识、归档SHA256、各表行数/内容摘要及媒体文件摘要。密钥另存，客户正文不写进验收报告。不要把两个独立平台快照当配套副本。
4. 备份必须保存在原Web磁盘之外的已批准位置，并确认可下载和解密。自动调度须在有持久执行环境上实现并监测成功/失败，不能靠某台电脑开机，也不能让Render cron访问Web磁盘；对象存储/外部调度如需新增账户或费用，先批准。保留策略自动删除前另审保护措施。
5. 在**全新隔离数据库和新图片目标**恢复，不连接或覆盖原环境，不自动打开邮件/AI/表单。核对表与图片摘要、发布状态、媒体引用、权限、登录以及迁移版本。记录耗时、目标、检查结果和原环境未改的证据。目标资源可能收费，先批准。恢复失败保留原环境，不能凭有备份文件判定成功。
6. 配套副本确认后，维护模式下手动部署新提交，Web先迁移，再部署同SHA的两worker；完成冒烟再退出维护模式。数据库若有不兼容变更，旧版本不能直接启动。
7. 回滚优先使用向前修复；只有确认旧代码兼容当前schema时回到旧提交。不要自动执行迁移down（历史SEO迁移有拒绝有损回退保护）。确需数据恢复，先保留故障环境副本，在新目标恢复并核验，再经批准切换连接；不得用旧备份直接覆盖现库。

现有 `compose:backup` / `compose:restore-test` 仅支持本机Docker回环环境，**不得用于Render**。平台账号未到位，配套自动备份执行器/密钥/连接命令与真实恢复证据均待下一步，不能把本地验证勾成完成。
